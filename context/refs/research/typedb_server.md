## Layout

Bazel-first monorepo (`BUILD` files everywhere; root `Cargo.toml` is generated — "Generated by TypeDB Cargo sync tool", workspace members at `Cargo.toml` line 159). Root package `typedb_server_bin` (edition 2024), entrypoint `main.rs`.

- `main.rs` — binary entry: parses `CLIArgs` (clap), loads `server/config.yml` via `ConfigBuilder`, builds a multi-thread tokio runtime, runs `ServerBuilder::default().build(config).await` then `server.serve().await`. Optional Sentry guard.
- `server/` — network layer. `server/lib.rs` (`ServerBuilder`, `Server`, `serve_grpc`/`serve_http`), `server/service/grpc/*` (tonic), `server/service/http/*` (axum), `server/service/admin/*` (local admin endpoint + its own proto crate `server/service/admin/proto`), `server/authentication/*` (JWT + password verify), `server/state/*` (`ServerState` + `DatabaseOperator`/`TransactionOperator`/`UserOperator`/`ServerOperator`), `server/parameters/{cli.rs,config.rs}`, `server/config.yml` (shipped default config).
- `database/` — DB lifecycle + transaction objects: `database.rs` (`Database<D>`), `database_manager.rs` (`DatabaseManager`, import ownership/cleanup), `transaction.rs` (`TransactionRead/Write/Schema`, commit intents), `migration/` (import/export).
- `storage/` — MVCC KV layer over **RocksDB**: `storage.rs` (`MVCCStorage<Durability>`, `MVCCKey`), `keyspace/` (`Keyspaces`, `rocks_resources.rs` shared block cache + write-buffer manager), `snapshot/` (`ReadSnapshot`/`WriteSnapshot`/`SchemaSnapshot`, `buffer.rs` `OperationsBuffer`, `write.rs` `Write`, `lock.rs` `LockType`), `isolation_manager.rs`, `recovery/{checkpoint.rs,commit_recovery.rs}`, `durability_client.rs` (`DurabilityClient` trait, WAL client).
- `durability/` — `durability.rs` (`DurabilityService` trait, `DurabilitySequenceNumber`), `wal.rs` (`WAL` struct, file-backed log in `wal/` dir, background `FsyncThread`).
- `encoding/` — all key layouts: `encoding.rs` (`EncodingKeyspace`, `Keyable`, RocksDB tuning per keyspace), `layout/prefix.rs` (the `Prefix` byte table), `graph/type_/*`, `graph/thing/*`, `graph/definition/*`, `value/*` (per-value-type byte encodings, `value_type.rs`).
- `concept/` — the concept model: `type_/` (types + `type_manager/`), `thing/` (instances + `thing_manager/`), shared `ConceptStatus` in `lib.rs`.
- Query stack: `ir/` (TypeQL AST → intermediate representation; `pattern/`, `pipeline/`, `translation/`), `compiler/` (`annotation/` = type inference, `executable/` = planning, `transformation/`), `executor/` (`pipeline/`, `match_executor.rs`, `read/`, `write/`, `instruction/`), `query/` (`query_manager.rs` `QueryManager`, `define.rs`/`redefine.rs`/`undefine.rs`, `query_cache.rs`), `function/` (`FunctionManager`, `FunctionCache` for TypeQL functions), `answer/` (`variable_value.rs` — value/concept results).
- `system/` — bootstrap system database: `schema.tql` (user/credentials model), `repositories.rs`, `concepts.rs`. `user/` — `user_manager.rs`, `permission_manager.rs` (`PermissionManager::exec_user_*_permitted`).
- `common/` — 11 micro-crates: `bytes` (`Bytes`/`ByteArray` inline-capable byte types), `error` (`typedb_error!` macro), `lending_iterator`, `logger`, `options` (`TransactionOptions`), `primitive`, `cache`, `concurrency`, `iterator`, `fail_point`, `structural_equality`.
- `resource/` — `constants.rs` (all magic numbers: `TIMELINE_WINDOW_SIZE`, `MONITORING_DEFAULT_PORT: u16 = 4104`, buffer inline sizes), `profile.rs` (commit/transaction profiling counters).
- `diagnostics/` — metrics, `monitoring_server.rs` (HTTP monitoring on 4104), `reporter.rs` (PostHog/Sentry phone-home).
- `admin/` — separate `typedb-admin` CLI binary (`admin/main.rs`) talking to the server over a Unix socket / Windows named pipe.
- `binary/` — launcher scripts + `typedb.service`; `tests/` — BDD/assembly/benchmark tests; `tool/`, `util/`, `docker/`, `config/` — packaging/dev tooling.

## Core flow

**Startup**: `main.rs` → `server/lib.rs::ServerBuilder::build` → `initialise_storage` opens data dir, `DatabaseManager::new` (`database/database_manager.rs`) loads every database directory; each `Database::open` (`database/database.rs`) loads WAL (`durability/wal.rs::WAL::load`), replays/recovers via `storage/recovery/commit_recovery.rs::load_commit_data_from` + latest checkpoint (`storage/recovery/checkpoint.rs`, dir `storage/checkpoint`), builds `MVCCStorage`, `TypeCache`, `FunctionCache`, `Statistics`, `QueryCache`, and starts three `IntervalRunner`s per DB (`_statistics_updater`, `_checkpointer`, `_cleanup_worker`). `server/system_init.rs` bootstraps the `_system` DB from `system/schema.tql`.

**Storage engine**: one logical database = 5 RocksDB instances ("keyspaces"), `EncodingKeyspace` in `encoding/encoding.rs`: `DefaultOptimisedPrefix11/15/16/17/25`, each with a fixed-length prefix extractor (11/15/16/17/25 bytes), partitioned bloom filters, LZ4 upper levels; keys are routed to the keyspace whose prefix-seek length matches their access pattern. Physical key = `[logical key][8B big-endian *inverted* SequenceNumber][1B op: Insert=0x00/Delete=0x01]` — `MVCCKey` in `storage/storage.rs` (line 728); versions of one key sort newest-first, deletes are tombstone entries; visibility = `mvcc_key.sequence_number() <= open_sequence_number` (`storage/iterator.rs::MVCCRangeIterator`).

**Key encoding of the graph** (`encoding/layout/prefix.rs` byte table):
- Type vertices: `[1B prefix][2B TypeID(u16)]` — `encoding/graph/type_/vertex.rs::TypeVertex` (prefixes `VertexEntityType`=0x0A, `VertexRelationType`=0x0B, `VertexAttributeType`=0x0C, `VertexRoleType`=0x0F). Max 65k types per kind.
- Object vertices (entities/relations): `[1B prefix][2B TypeID][8B ObjectID(u64)]` = 11 bytes — `encoding/graph/thing/vertex_object.rs::ObjectVertex` (`VertexEntity`=0x1E, `VertexRelation`=0x1F). IIDs allocated per-type from `Box<[AtomicU64]>` in `encoding/graph/thing/vertex_generator.rs::ThingVertexGenerator` (re-synced from storage by `Database::prepare_for_writes`).
- Attribute vertices: `[1B prefix=0x20][2B TypeID][AttributeID]`, value-encoded inline (8-byte short form) or 17-byte long form with a seahash content hash for large strings/structs (`vertex_attribute.rs::AttributeID`, hasher in `graph/common/value_hasher.rs`).
- Data edges, stored twice for bidirectional traversal: `EdgeHas`(0x82)/`EdgeHasReverse`(0x83), `EdgeLinks`(0x84)/`EdgeLinksReverse`(0x85) (relation↔player, role in the value), plus a player-to-player shortcut index `EdgeLinksIndex`(0x8C) — `encoding/graph/thing/edge.rs`.
- Schema edges: `EdgeSub/Owns/Plays/Relates` + reverses (0x64–0x6B) — `encoding/graph/type_/edge.rs`; schema properties/annotations under `PropertyTypeVertex`/`PropertyTypeEdge`; label→type index `IndexLabelToType`(0xB6); struct/function definitions under `DefinitionStruct`/`DefinitionFunction` keyed by `definition_key.rs`.

**Transaction model** (`database/transaction.rs` + `storage/snapshot/snapshot.rs`):
- Three kinds: `TransactionRead<D>` over `ReadSnapshot`, `TransactionWrite<D>` over `WriteSnapshot`, `TransactionSchema<D>` over `SchemaSnapshot`. All capture an `open_sequence_number` at the storage watermark (`MVCCStorage::open_snapshot_*`, which `wait_for_watermark`) — pure snapshot reads, no read locks.
- Writes never touch RocksDB until commit: buffered per-keyspace in `OperationsBuffer` (`storage/snapshot/buffer.rs`) as `Write::{Insert, Put{reinsert, known_to_exist}, Delete}` (`storage/snapshot/write.rs`) plus explicit exclusive locks (`snapshot/lock.rs`, used e.g. for uniqueness).
- Concurrency gate (`database/database.rs::reserve_write_transaction`/`reserve_schema_transaction`): many concurrent write txns; a schema txn is exclusive against all writes and other schema txns (FIFO reservation queue, timeout `TransactionError::WriteExclusivityTimeout`).
- Commit = optimistic validation (`MVCCStorage::snapshot_commit`, `storage/storage.rs` line 267): (1) serialize `CommitRecord` into WAL via `DurabilityClient::sequenced_write` → get commit `SequenceNumber`; (2) request group fsync (`WAL::request_sync`, `FsyncThread`); (3) `IsolationManager::validate_commit` (`storage/isolation_manager.rs`) checks this record against every concurrent committed record — in-memory ring of `TimelineWindow<TIMELINE_WINDOW_SIZE>` slabs, falling back to reading commit records from the WAL for long-running txns (`validate_concurrent_from_disk`); conflicts are `IsolationConflict::{DeletingRequiredKey, RequireDeletedKey, ExclusiveLock}` — i.e. snapshot isolation + delete/require and lock conflicts, with `Put` deduplication handled via `DependentPut` reinsertions; (4) on success, apply `WriteBatches` to RocksDB, mark `applied`, advance the watermark, and durably record a `StatusRecord(committed/aborted)`. Recovery replays WAL records newer than the checkpoint and re-validates any without a status.
- Schema commits additionally: `TypeManager::validate`, flush `Statistics` to WAL, then swap `TypeCache`/`FunctionCache`/statistics and reset `QueryCache` under the DB-wide `schema: RwLock<Schema>` (`SchemaCommitIntent::commit` in `database/transaction.rs`).

**Concept model** (`concept/`):
- Four kinds — `encoding/graph/type_/mod.rs::Kind::{Entity, Attribute, Relation, Role}`. Types are `Copy` wrappers over `TypeVertex`: `EntityType`, `RelationType`, `AttributeType`, `RoleType` (`concept/type_/*.rs`), unified by `TypeAPI` / `KindAPI` / `ObjectTypeAPI` traits (`concept/type_/mod.rs`). Subtyping = `EdgeSub` edges; ownership/roleplay capabilities = `Owns`/`Plays`/`Relates` edge wrappers (`concept/type_/{owns.rs,plays.rs,relates.rs}`) with annotations/constraints (`annotation.rs`, `constraint.rs`).
- `TypeManager` (`concept/type_/type_manager.rs`) answers all schema questions, hitting `TypeCache` (immutable snapshot of the whole schema, rebuilt on schema commit) or falling back to `TypeReader` storage reads; `TypeWriter` writes schema keys; `validation/` holds operation-time + commit-time schema validation.
- Instances: `Entity`, `Relation`, `Attribute` (uninstantiated `Object` union) in `concept/thing/*.rs`, all `ThingAPI` (`concept/thing/mod.rs`); `ThingManager` (`concept/thing/thing_manager.rs`) is the sole data read/write API — creates vertices via `ThingVertexGenerator`, maintains `Has`/`Links` (+ reverse and `LinksIndex`) edges, and `finalise()` runs commit-time cardinality/constraint validation; `statistics.rs` maintains per-type counts (persisted to WAL, used by the query planner and `QueryCache` invalidation).

**Query path** (crosses `query`→`ir`→`compiler`→`executor`): gRPC/HTTP handler → `QueryManager::{execute_schema, prepare_read_pipeline, prepare_write_pipeline}` (`query/query_manager.rs`) → typeql parse → `ir/translation` builds a pipeline IR → `compiler/annotation` infers types (using `TypeManager` + statistics) → `compiler/executable` plans executable stages → `executor/pipeline/*` stage executors (`match_.rs`, `insert.rs`, `delete.rs`, `fetch.rs`, modifiers) pull rows lazily via `lending_iterator`; rows are `answer::VariableValue`s, streamed back in batches.

## Public API

External programs speak one of three protocols; there is no embeddable library API (crates are internal).

- **gRPC** (primary, default `0.0.0.0:1729` — `server/config.yml`): proto defs are the external pinned dep `typedb-protocol` (git tag `3.12.0`, see `Cargo.lock`), generated with tonic/prost. `server/service/grpc/typedb_service.rs::GRPCTypeDBService` implements `typedb_protocol::type_db_server::TypeDb`: `connection_open`, `authentication_token_create`, `servers_all/get`, `users_*`, `databases_get/all/contains/create/delete`, `database_schema`/`database_type_schema`, `databases_import`/`database_export` (streaming), and `transaction` — a bidirectional stream; each stream spawns a `TransactionService` (`server/service/grpc/transaction_service.rs`) whose `listen()` loop dispatches `transaction::req::Req::{OpenReq, QueryReq, AnalyzeReq, StreamReq, CommitReq, RollbackReq, CloseReq}`. Auth = per-request interceptor `server/service/grpc/authenticator.rs` validating JWTs.
- **HTTP/JSON** (default `0.0.0.0:8000`, axum): routes in `server/service/http/typedb_service.rs::create_protected_router` — `/:version/databases[...]`, `/:version/users[...]`, `/:version/transactions/open|:id/query|commit|rollback|close|analyze`, one-shot `/:version/query`; unprotected: `/health`, `/:version/version`, `/:version/signin`. HTTP transactions live server-side in a UUID-keyed sender map (`server/service/http/transaction_service.rs`).
- **Auth**: `server/authentication/credential_verifier.rs::CredentialVerifier::verify_password` checks password hashes stored in the `_system` DB (schema `system/schema.tql`, access via `user/user_manager.rs`); `server/authentication/token_manager.rs::TokenManager` issues/validates JWTs (`jsonwebtoken`, random in-memory secret — all tokens die on restart).
- **Admin socket**: `admin/main.rs` `typedb-admin` CLI → local Unix socket/named pipe served by `server/service/admin` (own protobuf crate `server/service/admin/proto`).
- **Monitoring**: `diagnostics/monitoring_server.rs` on port 4104 (`resource/constants.rs::MONITORING_DEFAULT_PORT`).
- **In-process surface** (for forks/embedders): `server::ServerBuilder` (`server/lib.rs`) is the composition root — `ServerBuilder::new().server_state(...).shutdown_channel(...).admin_serve_override(...).build(config)`; below it, `database::DatabaseManager` + `TransactionRead/Write/Schema::open(database, options)` + `with_transaction_parts!` macro is the real programmatic API the tests use.

## Extension points

- **Durability backend**: `storage/durability_client.rs::DurabilityClient` trait (and `durability/durability.rs::DurabilityService`) — `MVCCStorage<Durability>` is generic over it; `WAL` is the only impl, but replication would slot in here (commit records are the replication log; `Database::prepare_for_writes` already anticipates externally-applied writes).
- **Keyspace definitions**: `storage/keyspace/keyspace.rs::KeyspaceSet` trait — `EncodingKeyspace` is one impl; per-keyspace RocksDB tuning lives in `KeyspaceSet::rocks_configuration`.
- **Key encodings**: add a `Prefix` variant in `encoding/layout/prefix.rs` (macro-generated table with byte, fixed/variable width, Schema/Data domain) + a `Keyable` type in `encoding/graph/...`.
- **Value types**: `encoding/value/value_type.rs` + a `*_bytes.rs` codec + an `AttributeID` variant in `encoding/graph/thing/vertex_attribute.rs`.
- **Server composition**: `ServerBuilder::server_state`/`admin_serve_override` (`server/lib.rs`), `server/state/*_operator.rs` traits (`ServerOperator`, `DatabaseOperator`, ...) — the seam the closed-source cluster edition layers on.
- **Fail-point testing**: `common/fail_point` + `fail_point!()` call sites throughout commit/recovery paths (enabled by env var, debug builds only), driven by `tests/assembly/fail_points.rs`.
- **Query stages**: new pipeline stage = IR node (`ir/pipeline`), annotation + executable in `compiler`, executor in `executor/pipeline`.

## Notes for integrators

- Build system of record is Bazel; the Cargo workspace is synced tooling output — don't hand-edit root `Cargo.toml`. Rust edition 2024.
- Data dir layout per database: `storage/` (5 RocksDB keyspaces + `checkpoint/`) and `wal/`; deleting `wal/` without `storage/` (or vice versa) is a detected corruption case (`STORAGE_DELETED_KEYSPACES_BUT_NOT_WAL` fail point, `StorageOpenError`).
- Commit durability ordering matters: WAL write + fsync happens *before* isolation validation result is known; an aborted commit still occupies a WAL sequence number with a `StatusRecord(false)`. Recovery must re-validate WAL-tail records lacking a status (`storage/recovery/commit_recovery.rs`).
- Long-running write transactions get slower to commit: validation walks every concurrent commit since `open_sequence_number`, spilling from the in-memory timeline (`TIMELINE_WINDOW_SIZE` in `resource/constants.rs`) to WAL reads.
- Isolation is snapshot isolation, not serializable: only delete-vs-require, require-vs-delete, and explicit exclusive-lock conflicts abort (`IsolationConflict`); blind `Insert`s never conflict; concept-layer code adds locks where uniqueness demands it.
- One schema transaction blocks all writes cluster-of-one-wide; schema commit also swaps the shared `TypeCache`/`FunctionCache`/`QueryCache`, so read txns opened before the swap keep the old cache via `Arc`.
- `TypeID` is `u16` — hard cap 65,536 types per kind; `ObjectID` is `u64` per type.
- HTTP and gRPC expose the same state (`server/state/ServerState`); tokens from `/signin` and `authentication_token_create` are interchangeable but node-local and restart-volatile.
- Diagnostics phone home by default (Sentry in `main.rs::may_initialise_error_reporting`, PostHog in `diagnostics/reporter.rs`); disabled via config `diagnostics.reporting` or `development_mode.enabled`.
- Ports: 1729 (gRPC), 8000 (HTTP, on by default), 4104 (monitoring) — defaults in `server/config.yml` and `resource/constants.rs`.
