## Layout

Repo: `argoproj/argo-cd` @ `62bc080` (v3 line, module `github.com/argoproj/argo-cd/v3`, Go 1.26). One multi-call binary: `cmd/main.go` dispatches on `filepath.Base(os.Args[0])` (or `ARGOCD_BINARY_NAME`) to per-component cobra commands.

- `cmd/argocd/commands` — `argocd` CLI (talks to the API server via `pkg/apiclient`).
- `cmd/argocd-server/commands/argocd_server.go` (`NewCommand()`) — API/UI server; implementation in `server/`.
- `cmd/argocd-repo-server/commands/argocd_repo_server.go` — manifest-rendering service; implementation in `reposerver/`.
- `cmd/argocd-application-controller/commands/argocd_application_controller.go` — reconciler; implementation in `controller/`.
- `cmd/argocd-applicationset-controller/commands/applicationset_controller.go` — controller-runtime manager; implementation in `applicationset/`.
- `cmd/argocd-commit-server/commands/argocd_commit_server.go` — pushes hydrated manifests to git (source-hydrator support); implementation in `commitserver/`.
- `cmd/argocd-cmp-server/commands` — Config Management Plugin sidecar server; implementation in `cmpserver/`.
- `cmd/argocd-dex/commands/argocd_dex.go` — `rundex` / `gendexcfg`: generates a dex config from `argocd-cm` settings and execs the dex binary (SSO federation).
- Also present: `cmd/argocd-git-ask-pass` (git credential helper over a socket), `cmd/argocd-k8s-auth` (cloud IAM exec-auth), `cmd/argocd-notification` (`notification_controller/`).
- `pkg/apis/application/v1alpha1/` — the CRD Go types: `types.go` (Application, AppProject spec pieces), `app_project_types.go` (`AppProject`), `applicationset_types.go`, `repository_types.go` (Repository/Cluster non-CRD config types), `generated.pb.go`/`generated.proto` (types are proto-serializable because they travel over the internal gRPC APIs).
- `gitops-engine/` — the gitops-engine is now an **in-repo Go module** (`module github.com/argoproj/argo-cd/gitops-engine/v3`, wired via `replace` in root `go.mod`): `pkg/cache` (cluster cache), `pkg/diff`, `pkg/sync`, `pkg/health`, `pkg/utils/kube`.
- `util/` — shared libs: `util/db` (ArgoDB persistence layer), `util/settings` (argocd-cm/argocd-secret settings manager), `util/lua` (health/action Lua VM), `util/helm`, `util/kustomize`, `util/git`, `util/oci`, `util/webhook` (git webhook handler), `util/app/discovery` (source-type + CMP detection), `util/argo` (resource tracking).
- `resource_customizations/` — per-GVK `health.lua` / `actions/` scripts, embedded via `resource_customizations/embed.go` (`//go:embed all:*` → `Embedded embed.FS`).
- `manifests/` — install YAML incl. CRDs; `ui/` — web UI; `server/extension` — proxy-extension framework; `applicationset/` — generators, webhook, progressive sync.

## Core flow

**CRDs** (group `argoproj.io/v1alpha1`, registered in `pkg/apis/application/v1alpha1/register.go`):

- `Application` (`types.go:68`): `Spec ApplicationSpec`, `Status ApplicationStatus`, plus a top-level `Operation *Operation` field — a requested sync is written to `.operation`, not to spec.
  - `ApplicationSpec` (`types.go:77`): `Source *ApplicationSource` / `Sources ApplicationSources` (multi-source; `HasMultipleSources()` — `Sources` wins over `Source`), `Destination ApplicationDestination{Server, Namespace, Name}` (Server XOR Name), `Project string`, `SyncPolicy *SyncPolicy`, `IgnoreDifferences []ResourceIgnoreDifferences{Group,Kind,Name,Namespace,JSONPointers,JQPathExpressions,ManagedFieldsManagers}`, `RevisionHistoryLimit *int64` (default 10, rollback/history depth), `Info`, `SourceHydrator *SourceHydrator` (dry source → hydrated branch flow).
  - `ApplicationSource` (`types.go:196`): `RepoURL`, `Path`, `TargetRevision`, `Chart`, `Ref`/`Name` (multi-source cross-refs), `TagPrefix`, and exactly one tool block: `Helm *ApplicationSourceHelm` (`ValueFiles`, `Parameters []HelmParameter{Name,Value,ForceString}`, `Values`/`ValuesObject *runtime.RawExtension`, `FileParameters`, `ReleaseName`, `Namespace`, `KubeVersion`, `APIVersions`, `SkipCrds`, `SkipTests`, `PassCredentials`), `Kustomize *ApplicationSourceKustomize` (`NamePrefix`, `NameSuffix`, `Images`, `CommonLabels/Annotations`, `Patches`, `Components`, `Replicas`, `Namespace`, `Version`), `Directory *ApplicationSourceDirectory` (recurse/jsonnet/include-exclude), `Plugin *ApplicationSourcePlugin` (name, `Env`, `Parameters`).
  - `SyncPolicy` (`types.go:1524`): `Automated *SyncPolicyAutomated{Prune,*bool SelfHeal,AllowEmpty,Enabled}` (`IsAutomatedSyncEnabled()` treats nil `Enabled` as true), `SyncOptions []string` (e.g. `ServerSideApply=true`, `CreateNamespace=true`, `PruneLast`, `ApplyOutOfSyncOnly=true`), `Retry *RetryStrategy{Limit, Backoff{Duration,Factor,MaxDuration}, Refresh}`, `ManagedNamespaceMetadata`.
  - `ApplicationStatus` (`types.go:1219`): `Resources []ResourceStatus`, `Sync SyncStatus` (Synced/OutOfSync/Unknown + revision(s)), `Health AppHealthStatus`, `History RevisionHistories` (trimmed to `RevisionHistoryLimit` by `appStateManager.persistRevisionHistory`, `controller/state.go:1254`), `Conditions`, `OperationState *OperationState` (phase from `gitops-engine/pkg/sync/common`), `SourceType(s)`, `SourceHydrator SourceHydratorStatus`.
- `AppProject` (`app_project_types.go:46`, spec at `types.go:2839`): `SourceRepos`, `Destinations`, `Roles []ProjectRole` (JWT-token RBAC), `ClusterResourceWhitelist/Blacklist []ClusterResourceRestrictionItem`, `NamespaceResourceWhitelist/Blacklist`, `SourceNamespaces` (apps-in-any-namespace), `SyncWindows []*SyncWindow{Kind,Schedule(cron),Duration,Applications,Namespaces}`, `OrphanedResources`, `DestinationServiceAccounts` (sync impersonation), `SourceIntegrity` (replaces deprecated `SignatureKeys`; merge logic in `AppProject.EffectiveSourceIntegrity()`).
- `ApplicationSet` (`applicationset_types.go:54`): `Spec.Generators []ApplicationSetGenerator` (`List`, `Clusters`, `Git`, `SCMProvider`, `ClusterDecisionResource`, `PullRequest`, `Matrix`, `Merge`, `Plugin`, + post-`Selector`), `Template ApplicationSetTemplate{ApplicationSetTemplateMeta, Spec ApplicationSpec}`, `TemplatePatch`, `GoTemplate/GoTemplateOptions`, `SyncPolicy *ApplicationSetSyncPolicy`, `Strategy` (progressive/RollingSync), `IgnoreApplicationDifferences`, `PreservedFields`; `Status` holds `Conditions` + per-app `ApplicationStatus` for progressive sync.

**repo-server rendering pipeline** (`reposerver/repository/repository.go`):
- gRPC `Service` (registered by `reposerver/server.go:NewServer`); entry `GenerateManifest` (line 645) → `runRepoOperation` (line 346: resolves revision via `newClientResolveRevision`/helm/OCI client, acquires per-repo lock, checks Redis manifest cache `reposerver/cache`) → `runManifestGen`/`runManifestGenAsync` (825/849) → package-level `GenerateManifests` (line 1740).
- `GenerateManifests` calls `GetAppSourceType` (line 1951; explicit tool block, else detection in `util/app/discovery`, with `.argocd-source.yaml` / `.argocd-source-<app>.yaml` overrides merged by `mergeSourceParameters` line 1896), then switches on `v1alpha1.ApplicationSourceType{Helm,Kustomize,Plugin,Directory}`:
  - Helm → `helmTemplate` (line 1285): dependency resolution + `helm template` exec via `util/helm/helm.go` (`helm.Template(opts)` shells out).
  - Kustomize → `kustomize.NewKustomizeApp(...).Build(...)` (`util/kustomize`).
  - Plugin → `runConfigManagementPluginSidecars` (line 2356): connects over unix socket in `common.GetPluginSockFilePath()` (default `/home/argocd/cmp-server/plugins`, `common/common.go:108`), streams a tarball of the repo to the CMP sidecar's `GenerateManifest(stream AppStreamRequest)` (`cmpserver/plugin/plugin.proto`).
  - Directory → `findManifests` (plain YAML/JSON/jsonnet).
  - Each rendered object gets tracking metadata via `argo.NewResourceTracking().SetAppInstance(...)` (label or `argocd.argoproj.io/tracking-id` annotation per `TrackingMethod`), then is JSON-marshaled into `ManifestResponse.Manifests`. `ARGOCD_APP_*` env (`newEnv`, line 1857) is exposed to all tools.

**application-controller reconcile** (`controller/appcontroller.go`):
- `ApplicationController` (line 118) holds five workqueues (`appRefreshQueue`, `appOperationQueue`, `appComparisonTypeRefreshQueue`, `projectRefreshQueue`, `appHydrateQueue`/`hydrationQueue`), an Application `SharedIndexInformer`, `stateCache statecache.LiveStateCache` and `appStateManager AppStateManager`. `Run(ctx, statusProcessors, operationProcessors, hydrationProcessors)` (line 942) starts informers, the live-state cache, and N goroutines per queue.
- Refresh path: `processAppRefreshQueueItem` (line 1825) → `needRefreshAppStatus` (line 2155: refresh timeout, `argocd.argoproj.io/refresh` annotation, requested `CompareWith` level; `ComparisonWithNothing` short-circuits to rebuilding only the cached resource tree) → `appStateManager.CompareAppState` (`controller/state.go:681`):
  - `GetRepoObjs` (state.go:228) calls repo-server `GenerateManifest` per source; live objects come from `LiveStateCache.GetManagedLiveObjs` (`controller/cache/cache.go:134`, backed by `gitops-engine/pkg/cache` watches).
  - Diff via `argodiff.StateDiffs` with a `diff.DiffConfigBuilder` (ignoreDifferences normalizers, `WithGVKParser`, optional server-side diff using a dry-run applier `getServerSideDiffDryRunApplier` in `controller/sync.go:70`, structured-merge diff when `ServerSideApply=true`) — all from `gitops-engine/v3/pkg/diff`. Per-resource `SyncStatusCode` computed at state.go:940-1080 (hooks/ignored/non-self-referenced resources excluded; project-forbidden GKs get `Unknown`).
  - Health: `setApplicationHealth` (`controller/health.go:25`) calls `health.GetResourceHealth(res.Live, lua.ResourceHealthOverrides(resourceOverrides))` — gitops-engine built-in checks, overridable by Lua: `util/lua/lua.go` `VM.GetHealthScript` prefers `argocd-cm` `resource.customizations.health.<group>_<kind>`, else embedded `resource_customizations/<group>/<Kind>/health.lua`; worst status wins, child Argo CD Apps' Missing/Unknown don't propagate.
  - Back in `processAppRefreshQueueItem`: resource tree cached (`setAppManagedResources` → Redis via `util/cache/appstate`), sync windows checked (`project.Spec.SyncWindows.Matches(app).CanSync`), `autoSync` (line 2519) — only when `SyncPolicy.IsAutomatedSyncEnabled()` and status is OutOfSync; sets `app.Operation = Operation{Sync: &SyncOperation{Prune: Automated.GetPrune(), ...}, InitiatedBy: {Automated: true}, Retry: {Limit: 5}}`, dedupes via `alreadyAttemptedSync`, self-heal attempts gated by `selfHealRemainingBackoff` (line 2711); status persisted with `persistAppStatus`.
- Operation path: `processAppOperationQueueItem` (line 1069) → `processRequestedAppOperation` (line 1518) → `appStateManager.SyncAppState` (`controller/sync.go:160`): re-compares, enforces sync windows + `validateSyncPermissions`, builds `sync.NewSyncContext` (sync.go:416) from `gitops-engine/v3/pkg/sync` with options mapped from `SyncOptions` (`WithServerSideApply`, `WithPruneLast`, `WithReplace`, `WithPrunePropagationPolicy`, `WithSyncWaveHook(delayBetweenSyncWaves)`, `WithHealthOverride(lua.ResourceHealthOverrides(...))` …) and runs `syncCtx.Sync(ctx)` — waves/hooks/prune live in gitops-engine. Result → `status.operationState`, history appended by `persistRevisionHistory`.
- Watch fan-in: cluster-cache change events call `handleObjectUpdated` (line 418) → `requestAppRefresh` with `CompareWithRecent`, so drift triggers self-heal without polling. Sharding across controller replicas: `controller/sharding`.
- Hydrator: `processAppHydrateQueueItem`/`processHydrationQueueItem` (lines 2075/2109) drive `controller/hydrator/hydrator.go`, which renders the dry source via repo-server, then calls commit-server `CommitService.CommitHydratedManifests` (`commitserver/commit/commit.proto`) to push hydrated manifests to `syncSource.TargetBranch`.

**applicationset-controller** (`applicationset/controllers/applicationset_controller.go`): controller-runtime `ApplicationSetReconciler.Reconcile` (line 119) → `template.GenerateApplications(logCtx, appset, r.Generators, r.Renderer, r.Client)` (generators in `applicationset/generators/*.go`, each implements `Generator.GenerateParams`; rendering in `applicationset/controllers/template` + `applicationset/utils` `Renderer` — fasttemplate or Go templates) → validate → create/update/delete `Application` objects per `ApplicationSetSyncPolicy` (create-only/create-update/create-delete/sync), owner references, optional progressive sync (`applicationset/progressivesync`). `applicationset/webhook` has its own webhook endpoint to nudge Git/PR generators.

## Public API

- `server/server.go` — `ArgoCDServer` (line 187) serves gRPC + grpc-gateway REST + UI on one port; services registered at line 1001-1015: `VersionService`, `ClusterService`, `ApplicationService`, `ApplicationSetService`, `NotificationService`, `RepositoryService`, `RepoCredsService`, `SessionService`, `SettingsService`, `ProjectService`, `AccountService`, `CertificateService`, `GPGKeyService`. Protos live next to implementations, e.g. `server/application/application.proto` `service ApplicationService`: `List/Watch/Create/Get/Update/UpdateSpec/Patch/Delete/Sync/Rollback/TerminateOperation/ManagedResources/ResourceTree/WatchResourceTree/ServerSideDiff/GetManifests/PodLogs/RunResourceActionV2/...`.
- `pkg/apiclient/` — the supported Go client for external programs (`apiclient.go` `NewClient`; per-service packages `pkg/apiclient/application`, `.../project`, etc.). The `argocd` CLI is built entirely on it.
- Git webhooks: `POST /api/webhook` on the API server (`server/server.go:1284`, handler `util/webhook`), GitHub/GitLab/etc payloads → app refresh + repo cache invalidation.
- Internal (not user-facing but callable) gRPC surfaces: repo-server `RepoServerService` (`reposerver/repository/repository.proto`: `GenerateManifest`, `GenerateManifestWithFiles`, `ResolveRevision`, `ListRefs`, `ListApps`, `GetAppDetails`, `GetRevisionMetadata`, `GetGitFiles`, `GetGitDirectories`, `UpdateRevisionForPaths`, …; client in `reposerver/apiclient`), commit-server `CommitService.CommitHydratedManifests` (`commitserver/apiclient`), CMP `ConfigManagementPluginService` (`cmpserver/apiclient`).
- Kubernetes API itself: everything is a CRD, so `kubectl apply` of `Application`/`AppProject`/`ApplicationSet` is a first-class API; generated typed clientset in `pkg/client/clientset/versioned` (used by the controller as `appclientset.Interface`).

## Extension points

- **Config Management Plugins** — sidecar containers running `argocd-cmp-server` with a `ConfigManagementPlugin` YAML (discover/generate/parameters commands, `cmpserver/plugin`); repo-server auto-discovers via socket dir + `MatchRepository`. This is the sanctioned "custom renderer" hook.
- **Lua health checks** — `argocd-cm` key `resource.customizations.health.<group>_<Kind>` or in-tree PR to `resource_customizations/<group>/<Kind>/health.lua`; executed by `util/lua/lua.go` `VM.ExecuteHealthLua`.
- **Lua resource actions** — `resource_customizations/**/actions/` (discovery.lua + per-action scripts), run through `ApplicationService.RunResourceActionV2` (`VM.ExecuteResourceAction`, can create/patch related resources).
- **ApplicationSet Plugin generator** — `applicationset/generators/plugin.go`: HTTP callout to your service returning parameter maps.
- **Proxy extensions / UI extensions** — `server/extension/extension.go` `ExtensionManager` proxies `/extensions/<name>` to backends declared in `argocd-cm` (`extension.config`); UI JS extensions load from the server's extensions dir.
- **Deep links** — `server/deeplinks`, templated URLs configured in `argocd-cm`.
- **Custom diff behavior** — `spec.ignoreDifferences` (JSON pointers / JQ / managedFieldsManagers) plus global `resource.customizations.ignoreDifferences` handled by `util/argo/normalizers`.
- **Sync hooks/waves** — annotations `argocd.argoproj.io/hook` and `argocd.argoproj.io/sync-wave`, interpreted by `gitops-engine/v3/pkg/sync/hook` and `pkg/sync/syncwaves`.
- **Auth** — dex (`cmd/argocd-dex`) or direct OIDC (`util/oidc`, `server/server.go` `ssoClientApp`); RBAC via `server/rbacpolicy` + casbin policies in `argocd-rbac-cm`.

## Notes for integrators

- **Persistence is Kubernetes-native only**: CRDs hold all app/project/appset state; repos, repo-creds and clusters are Secrets labeled `argocd.argoproj.io/secret-type` = `repository|repository-write|cluster|repo-creds` (`common/common.go:198`), accessed exclusively through `util/db` `ArgoDB` (`util/db/db.go:25`) — write those Secrets, not some internal API, to register clusters/repos declaratively. Settings live in the `argocd-cm`/`argocd-secret` ConfigMap/Secret via `util/settings.SettingsManager`. Redis is a throwaway cache (manifest cache `reposerver/cache`, app state/resource-tree cache `util/cache/appstate`) — safe to flush.
- **Triggering behavior programmatically**: request a sync by setting the Application's top-level `.operation` field (that's all `ApplicationService.Sync` does, cf. `autoSync` at `controller/appcontroller.go:2573`); request a refresh with the `argocd.argoproj.io/refresh: normal|hard` annotation (`needRefreshAppStatus`). Watch `.status.operationState.phase` (`Running/Succeeded/Failed/Error/Terminating` from `gitops-engine/v3/pkg/sync/common`) for completion.
- **gitops-engine moved in-repo** (`gitops-engine/` module, `replace` directive in `go.mod`); if you vendor Argo CD packages, imports are `github.com/argoproj/argo-cd/gitops-engine/v3/...`, no longer `github.com/argoproj/gitops-engine`.
- The controller talks to repo-server and commit-server only over gRPC clientsets (`reposerver/apiclient`, `commitserver/apiclient`) — you can stand in for either service by implementing the proto.
- Multi-source ordering matters: manifests are applied in `spec.sources` order, `ref:` sources contribute values files only; `spec.sourceHydrator` is mutually exclusive with `sources` (`ApplicationSpec.GetSource()` precedence: hydrator → sources[0] → source).
- Apps-in-any-namespace requires both controller/server `--application-namespaces` and `AppProjectSpec.SourceNamespaces`; RBAC names become `<project>/<appNs>/<app>` (`ApplicationSet.RBACName`, `security.RBACName`).
- The CRD types are proto-annotated; field numbers in `types.go` are wire contract for the internal gRPC APIs — never renumber when extending.
