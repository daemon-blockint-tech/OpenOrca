## Layout

- `controller/` — the application controller (the sync executor). `appcontroller.go` (3081 LoC): work queues, operation processing, auto-sync. `sync.go`: `SyncAppState` — bridges an Application operation into a gitops-engine sync. `state.go`: `CompareAppState`, `persistRevisionHistory`. `hook.go`: PreDelete/PostDelete hooks (deletion-time, outside the sync phases). `sync_namespace.go`: `syncNamespace` modifier for `CreateNamespace=true`. `controller/syncid/`: per-operation sync ID generation.
- `gitops-engine/` — vendored in-repo module `github.com/argoproj/argo-cd/gitops-engine/v3` (not an external dep anymore). `pkg/sync/sync_context.go` is the actual apply/prune/hook engine; `pkg/sync/sync_tasks.go` ordering; `pkg/sync/sync_phase.go` phase mapping; `pkg/sync/syncwaves/waves.go` wave parsing; `pkg/sync/hook/` hook detection + `HookFinalizer`; `pkg/sync/common/types.go` all annotation constants, `OperationPhase`, `ResultCode`, `HookType`; `pkg/sync/reconcile.go` `Reconcile()`/`ReconciliationResult` (splits hooks from managed resources, pairs target↔live).
- `server/application/application.go` — API server gRPC service: `Sync`, `Rollback`, `TerminateOperation` RPCs (service defined in `server/application/application.proto`, rpcs at lines 447/475/483).
- `pkg/apis/application/v1alpha1/types.go` — the data model: `Operation`, `SyncOperation`, `OperationState`, `SyncOperationResult`, `RevisionHistory`, `RetryStrategy`, `Backoff`, `SyncPolicy`, `SyncWindows`.
- `util/argo/argo.go` — `SetAppOperation` (the single write-path that starts any sync).
- `cmd/argocd/commands/app.go` — CLI: `NewApplicationSyncCommand`, `NewApplicationHistoryCommand`, `NewApplicationRollbackCommand` (thin wrappers over the RPCs).

## Core flow

**Trigger.** Every sync — manual, auto, or rollback — is started the same way: `util/argo/argo.go:SetAppOperation(appIf, appName, op)` writes `app.Operation = op` and nils `app.Status.OperationState`, retrying on conflict; it returns `ErrAnotherOperationInProgress` if `app.Operation != nil` (one op at a time per app, enforced optimistically).

**Controller loop.** `controller/appcontroller.go`:
- Informer events enqueue the app key onto `appOperationQueue` (rate-limited workqueue, created ~line 209); `shouldProcessOperation` = `app.Operation != nil || app.DeletionTimestamp != nil`.
- `processAppOperationQueueItem` (line 1069) re-fetches a fresh app (informer may be stale) and calls `processRequestedAppOperation` (line 1518).
- `processRequestedAppOperation`: if no in-progress state, seeds `NewOperationState` (`controller/sync.go:129`, phase=`Running`); if resuming a failed-with-retry op (`phase==Running && FinishedAt!=nil`) it computes `Operation.Retry.NextRetryAt(FinishedAt, RetryCount)` and either requeues (backoff not elapsed) or clears `SyncResult`/`FinishedAt` to start the attempt — with `Retry.Refresh` it also nulls `Sync.Revision(s)` so the retry uses the latest revision. Then calls `appStateManager.SyncAppState`. On `OperationFailed/Error` with retries remaining (`RetryCount < Retry.Limit || Limit < 0`) it flips the phase back to `Running` and sets `FinishedAt` — that unique combination is the "retry pending" marker. Finally `setOperationState` (line 1726) JSON-patches `/status/operationState` and, when the phase is terminal, patches `/operation` to `null`. A deferred `appOperationQueue.AddAfter(..., requeueAfter)` re-polls in-progress ops every `appOperationMaxRequeueInterval` (30s; 5s `appOperationRequeueDelay` batching on managed-resource change events). `--sync-timeout` flips a long-running op to `OperationTerminating`.

**Per-attempt sync.** `controller/sync.go:SyncAppState(ctx, app, project, state)`:
- Aborts early if `syncWindowPreventsSync(app, project)` (line 727) — `proj.Spec.SyncWindows.Matches(app).CanSync(isManual, operationStartTime)`.
- `CompareAppState` (`controller/state.go:681`) with `noRevisionCache=true`: repo-server renders manifests (`GetRepoObjs`), `liveStateCache.GetManagedLiveObjs` gets live objects, `gitops-engine/pkg/sync/reconcile.go:Reconcile` pairs them, `argodiff.StateDiffs` computes the diff list. The resolved concrete SHA is saved back into `state.SyncResult.Revision(s)` so a resumed operation keeps syncing the same commit even if the branch moved.
- Builds `[]sync.SyncOpt` and `sync.NewSyncContext(revision, reconciliationResult, restConfig, rawConfig, m.kubectl, namespace, opts...)`, then `syncCtx.Sync(ctx)` (or `Terminate` if phase is `OperationTerminating`), then `state.Phase, state.Message, resState = syncCtx.GetState()`.
- On success (non-dry-run, non-selective): `persistRevisionHistory`.

**Engine step (`gitops-engine/pkg/sync/sync_context.go:Sync`, line 493).** `Sync` is *resumable and idempotent* — the controller calls it repeatedly until a terminal phase:
- `getSyncTasks` (line 974) expands each resource into one `syncTask` per phase (`sync_phase.go:syncPhases` — plain resources get `SyncPhaseSync`; hooks get phases from `argocd.argoproj.io/hook`: `PreSync/Sync/PostSync/SyncFail`), names generateName hooks deterministically (`<generateName><rev7>-<phase>-<startedAtUnix>`), adds the `argocd.argoproj.io/hook-finalizer` finalizer, validates permissions per task, then **reverses prune waves** (symmetric swap of wave numbers so deletion runs in reverse creation order) and pushes `PruneLast` tasks to `lastSyncWave+1`.
- Ordering: `sync_tasks.go:Less` — phase (`PreSync=-1, Sync=0, PostSync=1, SyncFail=2`) → wave (`syncwaves/waves.go:Wave`, from `argocd.argoproj.io/sync-wave` annotation, falling back to Helm hook weight) → Helm-style `kindOrder` (Namespace→…→APIService) → name; `Sort()` then force-orders namespaces before their residents and CRDs before CRs (`adjustDeps`).
- First call runs a client-side dry-run of everything (after creating the app namespace if needed); subsequent calls update running-task status from live health (`health.GetResourceHealth`), wait if multi-step tasks/hooks are running or pruned objects still have deletion timestamps, and otherwise run the next `(phase, wave)` batch via `runTasks` (line 1626): prune first (parallel), then delete `BeforeHookCreation` hooks, then apply, grouped by kind.
- `applyObject` (line 1416): `resourceOps.ApplyResource` (kubectl apply; server-side if `ServerSideApply=true` via `shouldUseServerSideApply`, with CSA→SSA managedFields migration `performCSAUpgradeMigration`), or Replace/Create for `Replace=true` (CRDs/Namespaces get Update instead to avoid recreate). `pruneObject` (line 1488) deletes with `getDeleteOptions()` propagation policy; per-resource `Prune=false` → `ResultCodePruneSkipped`; `Prune=confirm` blocks the wave until `WithPruneConfirmed` (driven by `app.IsDeletionConfirmed`, the `argocd.argoproj.io/deletion-approved` annotation).
- Failure: tasks in `SyncPhaseSyncFail` run via `executeSyncFailPhase` (line 926); hooks with delete-policies `HookSucceeded/HookFailed` are cleaned by `deleteHooks`; success on last phase/wave with no hooks → `OperationSucceeded`.
- Between waves the controller-supplied `WithSyncWaveHook(delayBetweenSyncWaves)` (`controller/sync.go:713`) sleeps 2s (env `ARGOCD_SYNC_WAVE_DELAY`) to let other controllers react before health is assessed.

**Prune propagation.** `controller/sync.go:286-294`: `PrunePropagationPolicy=background|foreground|orphan` sync-option → `metav1.DeletionPropagation`, default **foreground**; passed via `sync.WithPrunePropagationPolicy`, consumed in `getDeleteOptions`.

**History.** `controller/state.go:persistRevisionHistory` (line 1254): appends a `v1alpha1.RevisionHistory{ID: last+1, Revision(s), Source(s), DeployedAt, DeployStartedAt, InitiatedBy}` to `app.Status.History`, truncates with `RevisionHistories.Trunc(app.Spec.GetRevisionHistoryLimit())` (default `RevisionHistoryLimit = 10`, `pkg/apis/application/v1alpha1/application_defaults.go`), merge-patches `/status/history`. Written **only** on successful, non-dry-run, non-selective (`len(syncOp.Resources)==0`) syncs. History = deployment log; it stores the *source spec + resolved SHA*, not manifests — rollback re-renders from the repo.

**Rollback.** `server/application/application.go:Rollback` (line 2264): RBAC action `rollback` if `server.rbac.rollback.enforce.enable` else `sync`; **refuses if `Spec.SyncPolicy.IsAutomatedSyncEnabled()`** (`"rollback cannot be initiated when auto-sync is enabled"` — it does *not* disable autosync for you; you must turn autosync off first or the next auto-sync would immediately roll forward again); finds `Status.History` entry by `rollbackReq.Id`; builds `Operation{Sync: &SyncOperation{Revision(s): deploymentInfo.Revision(s), Source: &deploymentInfo.Source, Sources: deploymentInfo.Sources, SyncStrategy: &SyncStrategy{Apply: ...}}}` and calls `SetAppOperation`. So a rollback is literally a sync with the historical source+SHA pinned — and because the strategy is `Apply`, hooks are skipped (`WithOperationSettings`'s `skipHooks` arg is `syncOp.IsApplyStrategy() || len(syncOp.Resources) > 0`). Pre-v0.12 history entries (no Source) are rejected.

**Auto-sync / self-heal.** `controller/appcontroller.go:autoSync` (line 2519), called from the refresh path (line 2004) after `CompareAppState`: fires only on `SyncStatusCodeOutOfSync`; default `Retry: RetryStrategy{Limit: 5}`; `alreadyAttemptedSync` (line 2676) compares last `SyncResult.Revision(s)`+source to avoid loops — a failed auto-sync to the same revision is **never retried** beyond the retry strategy (surfaced as `ApplicationConditionSyncError`); self-heal re-syncs on drift with backoff `selfHealRemainingBackoff` (line 2711, `SelfHealAttemptsCount` on the operation) and restricts to out-of-sync resources only.

**Retry math.** `types.go:RetryStrategy.NextRetryAt` (line 1573): `timeToWait = Duration * Factor^retryCount`, capped by `MaxDuration`; defaults 5s base, factor 2, cap 3m (`application_defaults.go`).

**Sync windows.** `AppProject.Spec.SyncWindows` (`types.go:2927`): cron `Schedule` + `Duration`, `Kind: allow|deny`, matched to apps by glob on app name/cluster/namespace (`Matches`, line 3106, OR by default, AND with `UseAndOperator`). `CanSync(isManual, opStartTime)` (line 3186): active deny blocks (unless `ManualSync` and manual, or `SyncOverrun` and the op started while allowed); defined-but-inactive allow windows also block. Enforced in three places: API server at sync submission (`application.go:2091`), controller before each engine step (`controller/sync.go:191` — an already-running op just parks with "Sync operation blocked by sync window"), and auto-sync gate (`appcontroller.go:2002`).

**Selective / apply-out-of-sync-only.**
- Selective sync: `SyncOperation.Resources []SyncOperationResource`; filtered per-resource in `sync.WithResourcesFilter` via `argo.ContainsSyncResource` (`controller/sync.go:388`). Skips hooks and skips history.
- `ApplyOutOfSyncOnly=true`: `sync.WithResourceModificationChecker(enabled, compareResult.diffResultList)`; engine's `filterOutOfSyncTasks` (sync_context.go:781) drops tasks whose diff said `!Modified` (hooks always kept).

## Public API

- gRPC/REST (`server/application/application.proto` → `server/application/application.go`): `ApplicationService.Sync(ApplicationSyncRequest)` (revision(s), prune, dryRun, strategy, resources, syncOptions, retryStrategy, local manifests), `ApplicationService.Rollback(ApplicationRollbackRequest{name, id, dryRun, prune})`, `ApplicationService.TerminateOperation` (line 2515). All return the updated `Application`.
- Declarative equivalent: any client may set `Application.operation` (`v1alpha1.Operation`) directly on the CR — that's all the RPCs do (`SetAppOperation`). Fleet-wide "recall bad version": iterate apps, disable autosync (`spec.syncPolicy.automated.enabled=false`), set `operation.sync` pinned to the good revision; roll forward = update `spec.source.targetRevision` and let autosync/`Sync` run.
- Embeddable engine API (what an external Go program calls): `gitops-engine/pkg/sync.NewSyncContext(revision, ReconciliationResult, restConfig, rawConfig, kubectl, namespace, ...SyncOpt) (SyncContext, cleanup, error)`; interface `SyncContext{Sync(ctx); Terminate(ctx); GetState() (OperationPhase, string, []ResourceSyncResult)}`; plus `sync.Reconcile(targetObjs, liveObjByKey, namespace, resInfo) ReconciliationResult`.
- Read surface for rollback tooling: `Application.status.history` (`RevisionHistories`, oldest→newest, monotonic `ID`), `status.operationState` (phase/message/syncResult/retryCount).

## Extension points

- `sync.SyncOpt` functional options (sync_context.go:78-243) — the entire engine configuration surface: `WithPermissionValidator`, `WithHealthOverride` (Argo CD plugs Lua health via `lua.ResourceHealthOverrides`), `WithResourcesFilter`, `WithSyncWaveHook`, `WithNamespaceModifier`, `WithResourceModificationChecker`, `WithPrunePropagationPolicy`, `WithServerSideApply(Manager)`, `WithClientSideApplyMigration`, etc.
- Resource annotations (constants in `gitops-engine/pkg/sync/common/types.go`): `argocd.argoproj.io/sync-wave`, `/hook`, `/hook-delete-policy`, `/sync-options` (`Prune=false|confirm`, `PruneLast=true`, `Replace=true`, `Force=true`, `ServerSideApply=true`, `SkipDryRunOnMissingResource=true`, `Validate=false`, `Delete=...`). Helm hook/weight annotations honored as fallback (`hook/helm`, `syncwaves.Wave`).
- Per-app knobs: `spec.syncPolicy` (automated/prune/selfHeal/allowEmpty/enabled, syncOptions, retry, managedNamespaceMetadata), `spec.revisionHistoryLimit`.
- Per-project: `AppProject.spec.syncWindows`, destinationServiceAccounts (sync impersonation — `settings.DeriveServiceAccountToImpersonate`, applied to both sync and server-side-diff dry-run in `controller/sync.go`).
- Env: `ARGOCD_SYNC_WAVE_DELAY` (inter-wave sleep). Server settings: `server.rbac.rollback.enforce.enable`, sync-with-replace kill switch (`s.syncWithReplaceAllowed`), `RequireOverridePrivilegeForRevisionSync`.

## Notes for integrators

- The engine is a **step function**, not a blocking call: `syncCtx.Sync()` performs at most one wave of work and returns; the controller's requeue loop provides the ticks. All resume state lives in `OperationState.SyncResult.Resources` (rehydrated via `WithInitialState`), keyed by `resourceKey:phase` (`resourceResultKey`) — so crash/restart resumes mid-operation.
- Rollback ≠ snapshot restore: it re-renders manifests from the historical `Source` at the historical SHA through the repo-server. If the repo rewrote history or the chart repo dropped the version, rollback fails. It also skips PreSync/PostSync hooks (Apply strategy) and does not touch `spec` — the app will show OutOfSync vs `spec.source.targetRevision` afterward.
- Autosync must be off for rollback (hard `FailedPrecondition`), and re-enabling it rolls forward again — a fleet recall tool has to sequence: disable autosync → rollback/pin → later re-enable.
- `alreadyAttemptedSync` means autosync will not hammer a failing revision: after the retry budget, the app parks with `ApplicationConditionSyncError` until the revision or source changes — recovery from a bad fleet push is "push the fix" or manual sync, not waiting.
- Prune ordering is handled for you: waves reversed for deletions, `PruneLast` after final wave, propagation default Foreground; but prune only happens when the operation's `Prune` flag is set (manual `--prune`, `automated.prune: true`, or rollback `prune` request field).
- Selective syncs leave no history and skip hooks — do not build audit trails on `status.history` if partial syncs are in play; use `status.operationState` events instead.
- `status.history` is capped (default 10, `spec.revisionHistoryLimit`); a rollback target older than the cap is gone — pin the revision via a normal `Sync` with explicit `revision` instead (subject to the `override` RBAC privilege when `RequireOverridePrivilegeForRevisionSync` is on).
