## Layout

- `server/` — the API server (`argocd-server` binary). One subdir per gRPC service: `server/application/`, `server/applicationset/`, `server/project/`, `server/account/`, `server/session/`, `server/cluster/`, `server/repository/`, `server/repocreds/`, `server/certificate/`, `server/gpgkey/`, `server/settings/`, `server/notification/`, `server/version/`. Each dir holds the `.proto` **and** the service impl (e.g. `server/application/application.proto` + `server/application/application.go`).
- `server/server.go` — wires everything: `ArgoCDServer.Run` → `newGRPCServer` (registers all services + auth interceptor) and `newHTTPServer` (grpc-gateway REST proxy, webhook endpoint, extensions, UI).
- `pkg/apiclient/` — generated Go client stubs, one package per service (`pkg/apiclient/application`, `.../account`, …) plus `pkg/apiclient/apiclient.go` — the `Client` interface every external Go program (and the CLI) uses.
- `pkg/apis/application/v1alpha1/` — the data model: `Application`, `AppProject`, `ApplicationSet` CRD types (`types.go`, proto mirror in `generated.proto`).
- `cmd/argocd/commands/` — CLI (reference client). `app.go`, `account.go`, `project_role.go`, `applicationset.go`, `login.go`; `cmd/argocd/commands/headless/headless.go` — "core mode" (spins up an in-process API server against kubeconfig, no argocd-server needed).
- `controller/` — `argocd-application-controller`: the reconciler that actually executes syncs (`controller/appcontroller.go`).
- `applicationset/` — ApplicationSet controller: `applicationset/controllers/applicationset_controller.go` (reconcile), `applicationset/generators/` (fan-out generators), `applicationset/controllers/template/template.go` (param → Application rendering), `applicationset/webhook/webhook.go` (its own webhook receiver), `applicationset/progressivesync/`.
- `util/webhook/webhook.go` — incoming git/registry webhook handling for the API server.
- `notification_controller/controller/controller.go` + `util/notification/` + `notifications_catalog/` — notifications subsystem (built on `github.com/argoproj/notifications-engine`).
- `util/session/sessionmanager.go`, `util/rbac/rbac.go`, `server/rbacpolicy/rbacpolicy.go`, `util/settings/accounts.go` — auth/RBAC machinery.
- `assets/model.conf`, `assets/builtin-policy.csv` — Casbin model + built-in roles.
- `util/db/db.go` — `ArgoDB` interface: clusters/repos persisted as Kubernetes Secrets in the argocd namespace.
- `reposerver/`, `commitserver/`, `cmpserver/` — internal manifest-generation gRPC services (API server and controller are their clients; not exposed externally).

## Core flow

- **Everything is a CR write.** The API server does not sync anything itself. `Sync` RPC (`server/application/application.go:2083`, `func (s *Server) Sync(ctx, *application.ApplicationSyncRequest) (*v1alpha1.Application, error)`) enforces RBAC (`applications, sync`), checks sync windows, resolves revisions via reposerver, builds a `v1alpha1.Operation{Sync: &v1alpha1.SyncOperation{...}, InitiatedBy: OperationInitiator{Username: session.Username(ctx)}}` and writes it into the Application's `.operation` field via `argo.SetAppOperation` (`util/argo/argo.go:950`).
- The application controller watches Applications, sees `.operation`, and executes it: `controller/appcontroller.go:1069 processAppOperationQueueItem` → `:1518 processRequestedAppOperation` (actual apply via the local `gitops-engine/` sync package). Result lands in `.status.operationState`. Clients poll/watch — the CLI's `argocd app sync --async=false` watches app status after the RPC (`cmd/argocd/commands/app.go` around line 2038).
- **`Rollback` is sync sugar** (`server/application/application.go:2264`): looks up `rollbackReq.Id` in `.status.history` (`RevisionHistory`), refuses if auto-sync enabled, then sets the same `Operation` with the historical revision/source. RBAC action is `sync` unless `server.rbac.rollback.enforce.enable` makes it `rollback`.
- **gRPC + REST are the same server.** `newGRPCServer` (`server/server.go:927`) registers `applicationpkg.RegisterApplicationServiceServer(grpcS, server.serviceSet.ApplicationService)` etc.; `newHTTPServer` (`server/server.go:1195`) creates a grpc-gateway `runtime.NewServeMux` with a custom `grpc_util.JSONMarshaler`, calls `mustRegisterGWHandler(ctx, applicationpkg.RegisterApplicationServiceHandler, gwmux, conn)` for every service, and mounts it at `/api/`. The gateway dials the gRPC port over localhost. gRPC-Web is handled via a content-type switch (`application/grpc-web+proto`). REST paths come from `option (google.api.http)` annotations in the protos.
- **Auth interceptor**: `grpc_auth.UnaryServerInterceptor(server.Authenticate)` / `StreamServerInterceptor` (`server/server.go:975,988`). `Authenticate` (`server/server.go:1560`) verifies the JWT (`SessionManager.VerifyToken`, `util/session/sessionmanager.go:556`) and stashes claims in `ctx` under key `"claims"`; every service method enforces with `s.enf.EnforceErr(ctx.Value("claims"), resource, action, object)`.
- **ApplicationSet reconcile** (`applicationset/controllers/applicationset_controller.go:119 Reconcile`): get AppSet → handle deletion (policy `AllowDelete`, reverse-deletion progressive sync, finalizer `argov1alpha1.ResourcesFinalizerName`) → `template.GenerateApplications(logCtx, appSet, r.Generators, r.Renderer, r.Client)` runs every generator's `GenerateParams` and renders one `Application` per param map → `validateGeneratedApplications` → optional progressive sync (`r.ProgressiveSyncManager.PerformProgressiveSyncs`, RollingSync strategy) → `createOrUpdateInCluster` (or `createInCluster` when policy forbids update) → `deleteInCluster` of orphans (when `AllowDelete`) → status conditions + `RequeueAfter` = min of generators' `GetRequeueAfter` (default `DefaultRequeueAfter = 3 * time.Minute`, env `ARGOCD_APPLICATIONSET_CONTROLLER_REQUEUE_AFTER`). Errors during generation requeue with `ReconcileRequeueOnValidationError` rather than erroring, so controller-runtime honors the delay.

## Public API

**Application service** (`server/application/application.proto`, REST base `/api/v1/applications`):
- `List` GET `/api/v1/applications`; `Get` GET `/{name}`; `Watch` (server-stream) GET `/api/v1/stream/applications`; `Create` POST; `Update` PUT `/{application.metadata.name}`; `UpdateSpec`; `Patch` PATCH `/{name}` (strategic-merge/JSON patch of the CR); `Delete` DELETE `/{name}`.
- `Sync` POST `/{name}/sync` (`ApplicationSyncRequest`: `revision`, `prune`, `dryRun`, `strategy`, `resources` for partial sync, `manifests` for local override — requires `override` RBAC, `syncOptions`, `retryStrategy`, `sourcePositions`/`revisions` for multi-source).
- `Rollback` POST `/{name}/rollback` (`ApplicationRollbackRequest{name, id, dryRun, prune}` — `id` from `.status.history`).
- `ResourceTree` GET `/{applicationName}/resource-tree` (+ `WatchResourceTree` stream at `/api/v1/stream/applications/{applicationName}/resource-tree`); `ManagedResources` GET `/{applicationName}/managed-resources`; `ServerSideDiff` GET.
- `PodLogs` (server-stream `LogEntry`) GET `/{name}/pods/{podName}/logs` and `/{name}/logs` (impl in `server/application/logs.go`).
- Resource-level: `GetResource`, `PatchResource`, `DeleteResource` under `/{name}/resource`; `ListResourceActions` GET `/{name}/resource/actions`; `RunResourceAction`/`RunResourceActionV2` POST `/{name}/resource/actions[/v2]` — Lua custom actions executed via `lua.VM.GetResourceAction`/`ExecuteResourceAction` (`server/application/application.go:2669`, scripts from `resource_customizations/` or `resourceOverrides`).
- `GetManifests`, `RevisionMetadata`, `RevisionChartDetails`, `GetOCIMetadata`, `TerminateOperation` DELETE `/{name}/operation`, `ListResourceEvents`, `GetApplicationSyncWindows`, `ListLinks`/`ListResourceLinks` (deep links).

**Other services an orchestrator needs**:
- Session (`server/session/session.proto`): `Create` POST `/api/v1/session` (`{username,password}` → JWT), `Delete`, `GetUserInfo` GET `/api/v1/session/userinfo`.
- Account (`server/account/account.proto`): `CanI` GET `/api/v1/account/can-i/{resource}/{action}/{subresource}`, `CreateToken` POST `/api/v1/account/{name}/token` (= `argocd account generate-token`), `DeleteToken`, `ListAccounts`, `UpdatePassword`.
- Project (`server/project/project.proto`): CRUD + `CreateToken` POST `/api/v1/projects/{project}/roles/{role}/token` (project-role JWT), `DeleteToken`, `GetSyncWindowsState`.
- ApplicationSet (`server/applicationset/applicationset.proto`): `List`/`Get`/`Create` (POST `/api/v1/applicationsets`, upsert flag)/`Delete`/`ResourceTree`/`Watch` (stream `/api/v1/stream/applicationsets`)/`Generate` POST (dry-run: returns the Applications a spec would produce — key for orchestrators).
- Notification: `ListTriggers`/`ListServices`/`ListTemplates` GET `/api/v1/notifications/*`. Plus cluster, repository, repocreds, certificate, gpgkey, settings, version services, all same pattern.
- Go client: `apiclient.NewClient(opts *ClientOptions) (Client, error)` (`pkg/apiclient/apiclient.go:181`) → `NewApplicationClientWithContext`, `NewProjectClientWithContext`, … returning generated `ApplicationServiceClient` etc. Auth token sent per-RPC via `jwtCredentials.GetRequestMetadata` (metadata key `token`); REST accepts `Authorization: Bearer` or cookie.
- CLI mapping: `argocd app sync` → `ApplicationService.Sync` (`cmd/argocd/commands/app.go:2038`); `argocd app rollback` → `ApplicationService.Rollback` (`app.go:2745`, `NewApplicationRollbackCommand` at `:2710`); `argocd account generate-token` → `AccountService.CreateToken` (`cmd/argocd/commands/account.go:401`).

**Machine auth model**:
- Local users: declared in `argocd-cm` (`accounts.<name>: apiKey,login`); parsed by `util/settings/accounts.go` (`Account`, `AccountCapabilityApiKey`, `AccountCapabilityLogin`); password hash + token metadata persisted in `argocd-secret` (`accounts.<name>.password`, `.tokens`).
- API tokens: `server/account/account.go:231 CreateToken` — requires `apiKey` capability, mints JWT via `SessionManager.Create(subject, expiresIn, id)` (`util/session/sessionmanager.go:176`; subject `"<name>:apiKey"`, signed with the server signature key, non-expiring if `expiresIn==0`), records token ID/issuedAt in the account so revocation works.
- Project-role tokens: `server/project/project.go:95 createToken` — subject `proj:<project>:<role>`, token IDs stored in `AppProject.Status.JWTTokensByRole`; policies live on the role (`AppProject.Spec.Roles[].Policies`), enforced by `server/rbacpolicy/rbacpolicy.go:149 enforceProjectToken` (scoped to that project only).
- RBAC: Casbin with custom model `assets/model.conf` (`r = sub, res, act, obj`, glob/regex matcher) + `assets/builtin-policy.csv` (`role:readonly`, `role:admin`). User policy from `argocd-rbac-cm` keys `policy.csv` / `policy.default` (`util/rbac/rbac.go:36`, live-reloaded by informer `RunPolicyLoader`). Object format for apps: `<project>/<app-ns>/<app-name>` (`Application.RBACName`); actions: `get/create/update/delete/sync/rollback/override/action/*`.

**Webhooks (inbound)**:
- API server: `mux.HandleFunc("/api/webhook", acdWebhookHandler.Handler)` (`server/server.go`). `util/webhook/webhook.go` `NewHandler` builds parsers for GitHub, GitLab, Bitbucket (cloud+server), Gogs, Azure DevOps (secrets from `argocd-cm` settings), plus GHCR/Harbor container-registry events (`util/webhook/ghcr.go`, `harbor.go`). `HandleEvent` (`:408`) extracts repo URLs/revision/changed files, matches every Application whose source uses the repo (`sourceUsesURL`, revision compare), queues a refresh (annotate app with refresh annotation via worker pool), and pre-invalidates/repopulates cached manifests (`storePreviouslyCachedManifests`). It refreshes; it never syncs directly (auto-sync policy decides).
- ApplicationSet controller runs its **own** webhook server: `startWebhookServer` mounts `/api/webhook` on `--webhook-addr` (default `:7000`) (`cmd/argocd-applicationset-controller/commands/applicationset_controller.go:296,335`); `applicationset/webhook/webhook.go NewWebhookHandler` triggers regeneration for Git/PullRequest generators on push/PR events.

**ApplicationSet generators (fleet fan-out)**:
- Interface: `applicationset/generators/interface.go` — `Generator{GenerateParams(gen, appSet, client) ([]map[string]any, error); GetRequeueAfter; GetTemplate}`.
- Registry: `applicationset/generators/utils.go GetGenerators` — `"List"` (`list.go`, inline `elements`), `"Clusters"` (`cluster.go`, params from Argo CD cluster Secrets: `name`, `server`, labels/annotations), `"Git"` (`git.go`, directories/files of a repo via reposerver), `"SCMProvider"`, `"PullRequest"`, `"ClusterDecisionResource"` (`duck_type.go`), `"Plugin"` (`plugin.go`, external HTTP param service), and combinators `"Matrix"` (`matrix.go`, cartesian product of 2 child generators) / `"Merge"` (`merge.go`) — matrix/merge get the terminal map so nesting is one level deep.
- Rendering: `applicationset/controllers/template/template.go GenerateApplications` — each param map is interpolated into `spec.template` (fasttemplate or Go-template per `goTemplate: true`); one `Application` per param set; ownership via owner references; orphan deletion controlled by `spec.syncPolicy` + controller `--policy` flag (`utils.DefaultPolicy(...).AllowUpdate()/AllowDelete()`).

**Notifications**:
- `notification_controller/controller/controller.go NewController` wraps `notifications-engine`'s `controller.NewController` with an `api.NewFactory(settings.GetFactorySettings(...))`; config from ConfigMap `argocd-notifications-cm` + Secret `argocd-notifications-secret` (`common/common.go:54-55`, parsing in `util/notification/settings/settings.go`).
- Model: `triggers` (named condition lists — CEL-ish expressions over `app` state, e.g. sync status/health transitions), `templates` (message bodies per service), `services` (slack/webhook/email/etc. — the `service.webhook.<name>` type lets a state change POST arbitrary JSON to any external endpoint = the hook an orchestrator subscribes with). Subscription via app/project annotations `notifications.argoproj.io/subscribe.<trigger>.<service>`. Stock catalog in `notifications_catalog/triggers/` and `templates/`. Trigger state is persisted on the Application's `notified.notifications.argoproj.io` annotation to dedupe.

**Persistence (all Kubernetes-native, no DB)**:
- `Application`/`AppProject`/`ApplicationSet` = CRDs (`pkg/apis/application/v1alpha1/types.go`). Sync intent = `.operation` field; result = `.status.operationState`; history = `.status.history`.
- Clusters and repositories = Secrets managed through `util/db/db.go ArgoDB` (`GetCluster`, `CreateRepository`, …).
- Accounts/settings/RBAC/notifications = ConfigMaps + Secrets (`argocd-cm`, `argocd-secret`, `argocd-rbac-cm`, `argocd-notifications-cm`), hot-reloaded (`server/server.go:804 watchSettings`, `:903 rbacPolicyLoader`).

## Extension points

- `server/extension/` + `registerExtensions` (`server/server.go:1329`) — proxy extensions: authenticated reverse-proxy routes under `/extensions/` to arbitrary backends (alpha, `EnableProxyExtension`).
- Lua: `resource_customizations/<group>/<kind>/actions/` — custom resource actions surfaced through `ListResourceActions`/`RunResourceActionV2`; health checks likewise (`util/lua/lua.go`).
- `deeplinks` (`server/deeplinks/`) — configured URL templates returned by `ListLinks`/`ListResourceLinks`.
- ApplicationSet `Plugin` generator (`applicationset/generators/plugin.go`) — your own HTTP service returns params; cleanest way to drive fleet membership from an external system without touching CRs.
- Notifications `service.webhook.<name>` — outbound calls on state change (the push channel to an orchestrator).
- gRPC reflection is enabled (`reflection.Register(grpcS)`, `server/server.go`) — clients can discover the API dynamically; REST schema in `assets/swagger.json`.

## Notes for integrators

- Sync is asynchronous by design: `Sync`/`Rollback` return as soon as `.operation` is set. Track completion via `Watch` (stream) or poll `Get` until `.status.operationState.phase` is terminal — exactly what the CLI's `waitOnApplicationStatus` does (`cmd/argocd/commands/app.go`).
- You can bypass the API server entirely: writing `Application`/`ApplicationSet` CRs (or `.operation`) directly to Kubernetes is equivalent — the API server is an RBAC/validation layer over the CRDs, and `argocd --core` (headless, `cmd/argocd/commands/headless/headless.go MaybeStartLocalServer`) does exactly that with kubeconfig auth.
- For a machine client: create a local account with `apiKey` in `argocd-cm`, grant it Casbin policy lines in `argocd-rbac-cm` (`p, <account>, applications, sync, <proj>/*, allow`), mint a token via `POST /api/v1/account/<name>/token`, send it as `Authorization: Bearer` (REST) or `token` metadata (gRPC). Project-role tokens are the tighter alternative when scope is a single project. Verify grants cheaply with `GET /api/v1/account/can-i/...`.
- REST non-GET requests require an allowed `Content-Type` (`application/json`) unless enforcement is disabled (`enforceContentTypes`, `server/server.go`) — a common 415 gotcha.
- `ApplicationSet.Generate` (POST, dry-run rendering) plus the `Plugin` generator are the two purpose-built hooks for fleet orchestration; per-app overrides inside a fleet go through generator params, not `Application.Patch` (the appset controller will fight manual edits when its policy allows update).
- Webhooks only shortcut the ~3-min git polling / appset requeue interval; idempotent to miss. Registry events (GHCR/Harbor) are also supported for OCI sources.
