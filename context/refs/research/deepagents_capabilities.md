## Layout

- Monorepo (pnpm workspaces): `libs/`, `examples/`, `evals/`, `internal/eval-harness/`, `scripts/`.
- `libs/deepagents/` — the core package, npm name `deepagents` (v1.13.0). Entry points: `src/index.ts` (full export surface), `src/node.ts` (re-export of index), `src/browser.ts` (browser-safe subset; excludes `FilesystemBackend`/`LocalShellBackend`/`LangSmithSandbox` per `package.json` `exports` map with a `browser` condition).
- `libs/deepagents/src/agent.ts` — `createDeepAgent()`, the single assembly point.
- `libs/deepagents/src/types.ts` — `CreateDeepAgentParams`, `DeepAgent`, `DeepAgentTypeConfig`, type-inference helpers (`InferSubagentByName`, `FlattenSubAgentMiddleware`, `InferStructuredResponse`, …).
- `libs/deepagents/src/middleware/` — all built-in capabilities are LangChain `createMiddleware(...)` instances: `fs.ts` (filesystem tools + result eviction), `subagents.ts` (task tool), `async_subagents.ts` (remote background subagents), `summarization.ts`, `skills.ts`, `memory.ts`, `agent-memory.ts`, `patch_tool_calls.ts`, `cache.ts`, `tool_exclusion.ts`, `completion_callback.ts`, `utils.ts` (`mergeMiddlewareStack`).
- `libs/deepagents/src/backends/` — pluggable storage/execution: `protocol.ts` + `v1/protocol.ts` + `v2/protocol.ts` (interfaces), `state.ts`, `store.ts`, `filesystem.ts`, `composite.ts`, `local-shell.ts`, `sandbox.ts` (`BaseSandbox`), `langsmith.ts`, `context-hub.ts`, `utils.ts` (v1→v2 adapters, string-replace, grep helpers).
- `libs/deepagents/src/permissions/` — `types.ts` (`FilesystemPermission`), `enforce.ts` (`validatePath`, `globMatch`, `decidePathAccess`).
- `libs/deepagents/src/profiles/harness/` — per-model "harness profiles" (`builtins/anthropic-*.ts`, `builtins/openai-codex.ts`, `create.ts`, `registry.ts`, `serialization.ts`).
- `libs/deepagents/src/skills/loader.ts` — direct-disk skill scanning (`listSkills`, `parseSkillMetadata`).
- `libs/acp/` — npm `deepagents-acp`: Agent Client Protocol server (`src/server.ts` `DeepAgentsServer`/`startServer`, `src/adapter.ts` ACP↔LangChain message translation, `src/acp-filesystem-backend.ts`) for Zed/JetBrains IDE integration.
- `libs/providers/` — sandbox/backends published separately: `daytona` (`DaytonaSandbox`), `modal` (`ModalSandbox`), `deno` (`DenoSandbox`) — all `extends BaseSandbox`; `node-vfs` (`VfsBackend implements BackendProtocolV2`); `quickjs` (`createCodeInterpreterMiddleware` — WASM JS REPL `eval` tool with programmatic tool calling).
- `libs/standard-tests/` — `@langchain/sandbox-standard-tests`, conformance suite for backend implementations (`src/tests/{read,write,edit,grep-raw,glob-info,ls-info,command-execution,...}.ts`).
- `examples/` — canonical usage: `backends/` (one file per backend class), `sandbox/` (daytona/modal/deno/langsmith/local/vfs), `research/research-agent.ts`, `hierarchical/`, `streaming/` (8 patterns), `memory/`, `skills-memory/`, `repl/`, `acp-server/`, `async-subagent-server/`, `async-subagents/parallel-research/`.

## Core flow

`libs/deepagents/src/agent.ts` `createDeepAgent(params)` builds a LangChain `createAgent` (LangGraph ReactAgent) with a deterministic middleware stack, then casts to `DeepAgent<...>`:

1. **Collision check** — user tool names vs `BUILTIN_TOOL_NAMES` (= `FILESYSTEM_TOOL_NAMES` + `ASYNC_TASK_TOOL_NAMES` + `"task"`) → `ConfigurationError("TOOL_NAME_COLLISION")` (`src/errors.ts`).
2. **Harness profile resolution** — `resolveHarnessProfile` (`src/profiles/`) picks a `HarnessProfile` from the model string/provider (builtins: `anthropic-haiku-4-5`, `anthropic-sonnet-4-6`, `anthropic-opus-4-7`, `openai-codex`). Profile controls `baseSystemPrompt`, `systemPromptSuffix`, `toolDescriptionOverrides`, `excludedTools`, `excludedMiddleware`, `extraMiddleware`, `generalPurposeSubagent` (`src/profiles/harness/types.ts`). `REQUIRED_MIDDLEWARE_NAMES` = `{FilesystemMiddleware, SubAgentMiddleware}` cannot be excluded.
3. **System prompt assembly** — `normalizeSystemPrompt` + `assemblePromptParts`: `prefix + (base ?? profile.baseSystemPrompt) + suffix + profile.systemPromptSuffix` (`SystemPromptConfig` in `src/compat.ts` is deprecated; pass a string/`SystemMessage`).
4. **Middleware stack** (order matters, merged via `mergeMiddlewareStack` in `src/middleware/utils.ts` — same-name custom middleware *replaces* the built-in in place):
   `[skills?] → FilesystemMiddleware → subAgentMiddleware → SummarizationMiddleware → patchToolCalls → [asyncSubAgentMiddleware?] → {custom middleware} → profile.extraMiddleware → [anthropicPromptCachingMiddleware + createCacheBreakpointMiddleware | bedrockPromptCachingMiddleware] → [memory?] → [humanInTheLoopMiddleware({interruptOn})?]`.
5. **Subagent normalization** — every declarative `SubAgent`/`ForkedSubAgent` gets its own default stack (`createSubagentDefaultMiddleware`): filesystem + summarization + patchToolCalls + optional per-subagent skills; `CompiledSubAgent` (has `runnable`) is used as-is. A `general-purpose` subagent mirroring the main agent (same model, tools, skills, custom middleware) is auto-prepended unless the profile disables it or the user supplies one named `general-purpose`.
6. Final graph: `createAgent({...}).withConfig({ recursionLimit: 10_000, metadata: { ls_integration: "deepagents" } })`.

**Filesystem tools** (`src/middleware/fs.ts`, `createFilesystemMiddleware`): registers `FILESYSTEM_TOOL_NAMES = ["ls","read_file","write_file","edit_file","delete","glob","grep","execute"]`. Every tool resolves the backend per-call via `resolveBackend(backend, runtime)` (`src/backends/protocol.ts`), checks `checkPermission(rules, op, path)` first, and returns `ToolMessage` or a LangGraph `Command({update:{files,messages}})` when the backend returns `filesUpdate` (checkpoint-backed backends). `read_file` paginates by lines (`offset`/`limit`, default 100 lines), returns multimodal blocks (`image`/`audio`/`video`/`file`) for binary MIME types (10MB cap `MAX_BINARY_READ_SIZE_BYTES`). `execute` is filtered out at `wrapModelCall` time unless `isSandboxBackend(resolvedBackend)`; `delete` is filtered by instance identity when the backend lacks `delete`. State channel: `files: Record<string, FileData>` with `fileDataReducer` (null = delete) — reusable as `filesValue` (`src/values.ts`).

**Large-result handling** (same file): `wrapToolCall` — any non-filesystem tool result > `toolTokenLimitBeforeEvict` (default 20 000 tokens at `NUM_CHARS_PER_TOKEN=4`) is written to `/large_tool_results/{toolCallId}.txt` via the backend and replaced with a head/tail preview (`createContentPreview`) + read_file instructions. `beforeAgent` similarly evicts oversized incoming `HumanMessage`s (> 50 000 tokens default) to `/conversation_history/{id}`, tagging `additional_kwargs.lc_evicted_to`; `wrapModelCall` swaps in the truncated view while state keeps the original.

**Summarization** (`src/middleware/summarization.ts`, `createSummarizationMiddleware({backend, trigger, keep, truncateArgsSettings,...})`): `wrapModelCall` counts tokens (`countTokensApproximately`), truncates old tool args, and when over threshold offloads evicted history to `{historyPathPrefix}/{session}.md` via the backend, summarizes with the request model (or configured `model`), and records a `_summarizationEvent {cutoffIndex, summaryMessage, filePath}` in state instead of rewriting messages; `getEffectiveMessages(messages, state)` reconstructs the visible window. Also catches `ContextOverflowError` for emergency summarization. Defaults from model profile: trigger 0.85×maxInputTokens / keep 0.10 (`computeSummarizationDefaults`); fallback 170k tokens / keep 6 messages.

**Subagents / task tool** (`src/middleware/subagents.ts`): `createSubAgentMiddleware` registers one `task` tool with schema `{description: string, subagent_type: string}`. `getSubagents()` compiles each spec via `createSubAgent(spec)` → `createAgent({model, systemPrompt, tools, middleware, responseFormat})`, adding `humanInTheLoopMiddleware` if the spec has `interruptOn`. On invocation: parent state is filtered (`filterStateForSubagent` drops `EXCLUDED_STATE_KEYS = [messages, todos, structuredResponse, skillsMetadata, memoryContents, _summarizationEvent, _summarizationSessionId]`); handoff mode gets only `[HumanMessage(description)]`, fork mode (`ForkedSubAgent`, `mode:"fork"`) gets parent effective history + description and inherits `parentSystemPrompt`. Result: subagent's final non-empty AI text (or JSON of `structuredResponse`) returned as a `ToolMessage` inside a `Command` that also merges the subagent's non-excluded state (files merge concurrently via reducer). Dynamic per-call response format via config key `SUBAGENT_RESPONSE_FORMAT_CONFIG_KEY` recompiles the spec.

**Async subagents** (`src/middleware/async_subagents.ts`): `AsyncSubAgent {name, description, graphId, url?, headers?}` targets any Agent Protocol server via `@langchain/langgraph-sdk` `Client`. Discriminated from sync subagents by `graphId` (`isAsyncSubAgent`). Adds 5 tools (`ASYNC_TASK_TOOL_NAMES`): `start_async_task`, `check_async_task`, `update_async_task`, `cancel_async_task`, `list_async_tasks`; tracks `AsyncTask` records in an `asyncTasks` state channel with `asyncTasksReducer`. Pairs with `createCompletionCallbackMiddleware` (`src/middleware/completion_callback.ts`) so a remote subagent can POST its final message back to a webhook.

**HITL**: no bespoke implementation — `createDeepAgent({interruptOn: Record<string, boolean | InterruptOnConfig>, checkpointer})` appends langchain's `humanInTheLoopMiddleware` at the stack tail; the same `interruptOn` is threaded to subagents as `defaultInterruptOn` (per-spec `interruptOn` overrides). Resume is standard LangGraph interrupt/`Command` resumption on a thread (see `evals/hitl/index.ts`).

**Todos**: not built in. `todoListMiddleware` comes from `langchain` and must be added via `middleware: [todoListMiddleware()]` (asserted in `src/agent.test.ts`); only the `openai-codex` profile auto-adds it via `extraMiddleware` (`src/profiles/harness/builtins/openai-codex.ts`).

**Skills** (`src/middleware/skills.ts`): `createSkillsMiddleware({backend, sources})` — `beforeAgent` scans each source dir through the backend for `SKILL.md` files (Agent Skills spec frontmatter: name ≤64 chars, description ≤1024, optional `license`, `compatibility`, `allowedTools`, `module` for QuickJS entrypoints), stores `skillsMetadata` in state + closure; `wrapModelCall` injects a skills listing into the system message (agent then `read_file`s the SKILL.md it needs — progressive disclosure). Custom subagents do NOT inherit main-agent skills; only general-purpose does.

**Memory**: two flavors. `createMemoryMiddleware({backend, sources, addCacheControl})` (`src/middleware/memory.ts`) — loads AGENTS.md-style files through the backend into `memoryContents` state and injects `<agent_memory>` + learning-guidelines prompt; agent self-edits memory with `edit_file`. Wired by `createDeepAgent({memory: [paths]})`; applied to main agent and forked subagents only. `createAgentMemoryMiddleware({settings, assistantId})` (`src/middleware/agent-memory.ts`) — CLI-style user (`~/.deepagents/{agent}/agent.md`) + project (`.deepagents/agent.md`) memory using `Settings` from `src/config.ts` (`createSettings`, `findProjectRoot`).

## Public API

All from `deepagents` (`libs/deepagents/src/index.ts`):

- `createDeepAgent<...>(params: CreateDeepAgentParams): DeepAgent<...>` — params: `model` (default `"anthropic:claude-sonnet-4-6"`), `tools`, `systemPrompt`, `stateSchema`, `middleware`, `subagents` (mixed `SubAgent | CompiledSubAgent | ForkedSubAgent | AsyncSubAgent` = `AnySubAgent`), `responseFormat`, `contextSchema`, `checkpointer`, `store`, `backend` (default `StateBackend`), `interruptOn`, `name`, `memory: string[]`, `skills: string[]`, `permissions: FilesystemPermission[]`, `streamTransformers`.
- Running it: standard LangGraph `agent.invoke(state, config)` / `agent.stream(state, {streamMode, subgraphs: true})`; typed v3 streaming `agent.streamEvents(state, {version: "v3"})` → `DeepAgentRunStream` with `run.messages/.toolCalls/.subagents/.middleware/.values/.output/.extensions` (`src/stream.ts`, `src/types.ts`).
- Middleware factories: `createFilesystemMiddleware`, `createSubAgentMiddleware`, `createSummarizationMiddleware` (+ re-exported base `summarizationMiddleware`), `createPatchToolCallsMiddleware`, `createMemoryMiddleware`, `createAgentMemoryMiddleware`, `createSkillsMiddleware`, `createAsyncSubAgentMiddleware`, `createCompletionCallbackMiddleware`.
- Backends: `StateBackend` (files in LangGraph state; zero-arg reads via `__pregel_read`, writes via `__pregel_send`; legacy runtime-injected constructor deprecated), `StoreBackend` (LangGraph `BaseStore`, `{store?, namespace?: string[] | StoreBackendNamespaceFactory}`), `FilesystemBackend` (`{rootDir?, virtualMode?, maxFileSizeMb?}`; O_NOFOLLOW, ripgrep-backed grep, lexical root containment in virtual mode), `CompositeBackend(defaultBackend, routes)` (longest-prefix routing, e.g. `"/memories/": new StoreBackend()`), `LocalShellBackend` (FilesystemBackend + unrestricted host `execute`; `{timeout=120s, maxOutputBytes=100_000, env, inheritEnv, initialFiles}`), `BaseSandbox` (abstract: implement `execute`, `uploadFiles`, `downloadFiles`; POSIX-shell default impls of ls/read/grep/glob), `LangSmithSandbox` (`LangSmithSandbox.create({snapshotId,...})`), `ContextHubBackend` (LangSmith Hub agent-repo storage with commit/conflict retry).
- Backend contract: `BackendProtocolV2` (`src/backends/v2/protocol.ts`) — `ls(path): LsResult`, `read(filePath, offset?, limit?): ReadResult`, `readRaw: ReadRawResult`, `write(filePath, content): WriteResult`, `edit(filePath, old, new, replaceAll?): EditResult`, `grep(pattern, path?, glob?, maxCount?): GrepResult`, `glob(pattern, path?): GlobResult`, optional `delete`, optional `uploadFiles`/`downloadFiles`; all `MaybePromise`. `SandboxBackendProtocolV2` adds `execute(command): ExecuteResponse {output, exitCode, truncated}` and `readonly id: string`. V1 (`lsInfo/grepRaw/globInfo`, string-returning `read`) is deprecated; `adaptBackendProtocol`/`adaptSandboxProtocol` (`src/backends/utils.ts`) upgrade v1→v2, and `resolveBackend` normalizes instance-or-factory to v2.
- Harness profiles: `createHarnessProfile`, `registerHarnessProfile`, `getHarnessProfile`, `serializeProfile`, `parseHarnessProfileConfig`, `EMPTY_HARNESS_PROFILE`.
- Misc: `filesValue`, `listSkills`/`parseSkillMetadata`, `createSettings`/`findProjectRoot`, `SandboxError`, `isSandboxBackend`/`isSandboxProtocol`, `applyGrepMaxCount`, `SUBAGENT_RESPONSE_FORMAT_CONFIG_KEY`, `createSubAgent`, `GENERAL_PURPOSE_SUBAGENT`, prompt constants in `src/compat.ts` (deprecated).

## Extension points

- **Custom backend** — implement `BackendProtocolV2` (or extend `BaseSandbox` for exec-capable ones) and pass as `backend:`. Validate with `@langchain/sandbox-standard-tests` (`libs/standard-tests/src/index.ts`). Providers show the pattern: `libs/providers/daytona/src/sandbox.ts`, `modal`, `deno`, `node-vfs/src/backend.ts`.
- **Custom middleware** — `middleware: [createMiddleware({name, stateSchema, tools, beforeAgent, wrapModelCall, wrapToolCall})]`; a middleware whose `name` matches a built-in *replaces* it in-place (`mergeMiddlewareStack`, `appendNew` option).
- **Subagents** — declarative `SubAgent` (isolated, own prompt/tools/model/skills/permissions/responseFormat/interruptOn), `ForkedSubAgent` (`mode:"fork"`, inherits history+parent prompt, no own systemPrompt), `CompiledSubAgent` (`{name, description, runnable}` — any Runnable, incl. another `createDeepAgent` result: `examples/hierarchical/hierarchical-agent.ts`), `AsyncSubAgent` (remote Agent Protocol server).
- **Harness profiles** — `registerHarnessProfile(spec, profile)` for new models; profile hooks cover prompt, tool descriptions, tool/middleware exclusion, extra middleware, GP-subagent config.
- **Permissions** — `FilesystemPermission {operations: ("read"|"write")[], paths: absolute-glob[], mode?: "allow"|"deny"}`, first-match-wins, permissive default; per-subagent `permissions` fully replaces parent's. Enforced only on fs tools — combining permissions with an exec-capable backend throws unless `execute` is disabled or a `CompositeBackend` scopes all paths to route prefixes (`src/middleware/fs.ts` `allPathsScopedToRoutes`).
- **Streaming** — `streamTransformers` factories surface under `run.extensions` in v3 streams.
- **MCP** — no MCP client in this repo. External tools are plain LangChain `tool()` instances (`examples/research/research-agent.ts` uses `@langchain/tavily`); MCP appears only as a passthrough capability declaration in the ACP server (`libs/acp/src/server.ts` `mcpCapabilities`). Wire MCP via LangChain's MCP adapters producing tools, then pass into `tools:`.
- **Code interpreter** — `@langchain/quickjs` `createCodeInterpreterMiddleware` adds an `eval` REPL tool (WASM-isolated, VFS-bridged, programmatic tool calling with `DEFAULT_MAX_PTC_CALLS` budget); skills can declare a `module` entrypoint for it (`examples/repl/`).

## Notes for integrators

- The returned agent IS a LangGraph ReactAgent — checkpointers, stores, `thread_id` config, interrupts, and `Command` resumption all behave as in LangGraph. `recursionLimit` is pre-set to 10 000.
- Backend choice decides persistence semantics: `StateBackend` files live in the checkpointed thread (`files` channel); `StoreBackend` is cross-thread via `BaseStore` namespaces; `FilesystemBackend`/`LocalShellBackend` write straight to disk (they return `filesUpdate: null` — no state round-trip); `CompositeBackend` mixes them by path prefix. Zero-arg `StateBackend` writes go through LangGraph's `__pregel_send` channel — the deprecated `filesUpdate` return only exists for legacy factory-mode backends.
- Tool names `ls, read_file, write_file, edit_file, delete, glob, grep, execute, task, start/check/update/cancel_async_task(s), list_async_tasks` are reserved; supplying a colliding tool throws at construction.
- `execute` and `delete` silently disappear from the model's tool list when the resolved backend lacks the capability — no error at construction.
- Prompt caching for Anthropic models is automatic (`anthropicPromptCachingMiddleware` + `createCacheBreakpointMiddleware` in `src/middleware/cache.ts`); Bedrock gets `bedrockPromptCachingMiddleware`.
- Type inference is aggressive: pass `subagents`/`middleware` `as const` to get typed `structuredResponse`, middleware state on `result`, and typed `run.subagents` streams.
- The Python library is the reference (`index.ts` claims 1:1 compat); several APIs are transitional — v1 backend protocol, `SystemPromptConfig`, `BackendFactory`, runtime-injected backend constructors are all `@deprecated` but still accepted.
- IDE embedding: `deepagents-acp` `startServer({agents: [{name, description, skills, memory}], workspaceRoot})` exposes any deep agent over Agent Client Protocol (Zed/JetBrains); `examples/acp-server/server.ts` is the canonical setup.
- For remote/parallel orchestration see `examples/async-subagent-server/` (supervisor + Agent Protocol server) and `examples/async-subagents/parallel-research/` (supervisor, researcher, and a Vite UI polling `asyncTasks`).
