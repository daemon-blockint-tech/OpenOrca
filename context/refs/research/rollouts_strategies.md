## Layout

- `pkg/apis/rollouts/v1alpha1/types.go` — the Rollout CRD data model: `Rollout`, `RolloutSpec` (incl. `WorkloadRef *ObjectRef` for the Deployment-replacement mode), `RolloutStrategy{BlueGreen,Canary}`, `BlueGreenStrategy` (`ActiveService`, `PreviewService`, `AutoPromotionEnabled *bool`, `AutoPromotionSeconds int32`, `ScaleDownDelaySeconds *int32`, `AbortScaleDownDelaySeconds`, `PrePromotionAnalysis`/`PostPromotionAnalysis *RolloutAnalysis`), `CanaryStrategy` (`Steps []CanaryStep`, `TrafficRouting *RolloutTrafficRouting`, `Analysis *RolloutAnalysisBackground`, `DynamicStableScale`, `PingPong`), `CanaryStep` (one-of `SetWeight *int32`, `Pause *RolloutPause`, `Analysis *RolloutAnalysis`, `Experiment *RolloutExperimentStep`, `SetCanaryScale *SetCanaryScale`, `SetHeaderRoute`, `SetMirrorRoute`, `Plugin *PluginStep`), `RolloutTrafficRouting` (Istio/Nginx/ALB/SMI/Ambassador/AppMesh/Traefik/Apisix/`Plugins map[string]json.RawMessage`/`ManagedRoutes`), `RolloutStatus` (`Abort`, `AbortedAt`, `PauseConditions`, `ControllerPause`, `CurrentStepIndex`, `StableRS`, `CurrentPodHash`, `PromoteFull`, `Phase RolloutPhase` ∈ Healthy/Degraded/Progressing/Paused).
- `pkg/apis/rollouts/v1alpha1/analysis_types.go` — `AnalysisTemplate`, `ClusterAnalysisTemplate`, `AnalysisRun`, `AnalysisTemplateSpec{Metrics,Args,DryRun,MeasurementRetention,Templates}`, `Metric` (`SuccessCondition`, `FailureCondition`, `FailureLimit`, `InconclusiveLimit`, `ConsecutiveErrorLimit`, `ConsecutiveSuccessLimit`, `Count`, `Interval`, `Provider MetricProvider`), `MetricProvider` (one-of Prometheus/Kayenta/Web/Datadog/Wavefront/NewRelic/Job/CloudWatch/Graphite/Influxdb/SkyWalking/`Plugin`), `AnalysisPhase` enum (Pending/Running/Successful/Failed/Error/Inconclusive), `MetricResult`, `Measurement`, `RunSummary`.
- `pkg/apis/rollouts/validation/` — spec + referenced-resource validation (used by `rollout/controller.go:getRolloutValidationErrors`).
- `rollout/` — the Rollout controller: `controller.go` (workqueue + `syncHandler`), `context.go` (`rolloutContext`), `bluegreen.go`, `canary.go`, `sync.go` (ReplicaSet revision sync, status calc, promotion), `analysis.go` (creating/canceling AnalysisRuns, abort-on-failure), `pause.go` (`pauseContext`), `trafficrouting.go`, `service.go` (selector switching), `replicaset.go` (scale-down-deadline annotations), `experiment.go`, `stepplugin.go`, `restart.go`, `ephemeralmetadata.go`, `templateref.go` (workloadRef resolution via dynamic informer).
- `rollout/trafficrouting/` — one subpackage per router (`istio/`, `nginx/`, `alb/`, `smi/`, `ambassador/`, `appmesh/`, `traefik/`, `apisix/`, `plugin/`) + the shared interface in `trafficroutingutil.go`.
- `analysis/` — the AnalysisRun controller: `controller.go`, `analysis.go` (measurement scheduling + assessment), `sync.go` (status persistence).
- `metric/provider.go` — the `Provider` interface all metric providers implement.
- `metricproviders/` — provider implementations (`prometheus/`, `datadog/`, `webmetric/`, `job/`, `wavefront/`, `newrelic/`, `cloudwatch/`, `graphite/`, `influxdb/`, `skywalking/`, `kayenta/`, `plugin/`) + `metricproviders.go` factory.
- `experiments/` — Experiment controller (ephemeral ReplicaSets + their own AnalysisRuns).
- `controller/controller.go` — `Manager` that wires and runs all five controllers (rollout, service, ingress, experiment, analysis) with leader election; `cmd/rollouts-controller/main.go` is the binary.
- `pkg/kubectl-argo-rollouts/` — kubectl plugin: `cmd/promote/`, `cmd/abort/`, `cmd/undo/`, `cmd/retry/`, `cmd/get/`, `cmd/dashboard/`, plus `viewcontroller/` and `info/` for status rendering.
- `pkg/apiclient/rollout/rollout.proto` — gRPC/REST `RolloutService` consumed by the dashboard UI (`server/`, `ui/`).
- `utils/` — the real logic lives here more than you'd expect: `utils/replicaset/canary.go` (weight→replica math, `GetCurrentCanaryStep`), `utils/analysis/` (template flattening, run construction), `utils/evaluate/evaluate.go` (expr-based condition evaluation), `utils/rollout/rolloututil.go` (phase calculation), `utils/plugin/` (plugin download + config), `utils/config/config.go` (plugin ConfigMap parsing).

## Core flow

- `controller/controller.go:NewManager` builds informers/workqueues for all controllers; `Manager.Run` starts them after leader election (`startLeading`). Everything is standard client-go informer + rate-limited workqueue.
- **Rollout reconcile**: `rollout/controller.go:syncHandler` → `newRolloutContext` (classifies ReplicaSets via `replicasetutil.FindNewReplicaSet`/`GetStableRS` into `newRS`/`stableRS`/`otherRSs`, gathers current AnalysisRuns/Experiments) → `rollout/context.go:(*rolloutContext).reconcile()`: check paused conditions → `isScalingEvent` short-circuit (`syncReplicasOnly`) → dispatch `rolloutBlueGreen()` or `rolloutCanary()`.
- **Blue/green** (`rollout/bluegreen.go:rolloutBlueGreen`): reconcile preview service selector → ReplicaSets → `reconcileBlueGreenPause` (pauses iff `needsBlueGreenControllerPause`: `autoPromotionEnabled=false` or `autoPromotionSeconds>0`; requires `completedPrePromotionAnalysis()`; timed self-resume via `checkEnqueueRolloutDuringWait`) → `reconcileActiveService` (switches `activeService` selector to the new pod-template-hash via `rollout/service.go:switchServiceSelector`) → `awsVerifyTargetGroups` → `reconcileAnalysisRuns` → `syncRolloutStatusBlueGreen`. Old RS scale-down honors `scaleDownDelaySeconds` via the `scale-down-deadline` annotation set in `rollout/replicaset.go:addScaleDownDelay`.
- **Canary** (`rollout/canary.go:rolloutCanary`): ephemeral metadata → ping/pong + stable/canary services → `reconcileTrafficRouting` (`rollout/trafficrouting.go`, calls `UpdateHash`/`SetWeight`/`SetHeaderRoute`/`SetMirrorRoute`/`VerifyWeight` on each reconciler) → experiments → `reconcileAnalysisRuns` → `reconcileCanaryReplicaSets` (replica math from `utils/replicaset/canary.go:CalculateReplicaCountsForBasicCanary` / `CalculateReplicaCountsForTrafficRoutedCanary`) → `reconcileCanaryPause` → step plugins → `syncRolloutStatusCanary`, which calls `completedCurrentCanaryStep()` (per-step-type completion switch) and increments `status.currentStepIndex`. Full promotion decided by `rollout/sync.go:shouldFullPromote` → `promoteStable` (sets `status.stableRS = currentPodHash`, clears pause/abort).
- **Analysis runs from the rollout side** (`rollout/analysis.go:reconcileAnalysisRuns`): creates/cancels the four kinds — `reconcileStepBasedAnalysisRun`, `reconcileBackgroundAnalysisRun`, `reconcilePrePromotionAnalysisRun`, `reconcilePostPromotionAnalysisRun` — labeled via `utils/analysis/factory.go:StepLabels/BackgroundLabels/PrePromotionLabels/PostPromotionLabels` and built by `newAnalysisRunFromRollout` → `utils/analysis/helpers.go:NewAnalysisRunFromTemplates` (flattens referenced `AnalysisTemplate`s/`ClusterAnalysisTemplate`s with `FlattenTemplates`, merges args).
- **Abort/rollback on failed analysis**: run phase `Failed`/`Error` → `pauseContext.AddAbort(message)` (canary: `rollout/analysis.go:379-384,437-442`; blue/green: `setPauseOrAbortForBlueGreen`; experiments: `rollout/experiment.go:199`; step plugins: `rollout/stepplugin.go:138`; progressDeadline: `rollout/sync.go:evaluateProgressDeadlineAbort`). `Inconclusive` → `AddPauseCondition(PauseReasonInconclusiveAnalysis)` (halts everything via `context.go:haltProgress`). `rollout/pause.go:CalculateAbortStatus` persists `status.abort`/`status.abortedAt`. On abort, canary sets step index back to 0 (`syncRolloutStatusCanary`), stable RS is scaled up, traffic weight goes to 0/stable (`rollout/trafficrouting.go:calculateDesiredWeightOnAbortOrStableRollback`), and the canary RS scale-down obeys `abortScaleDownDelaySeconds` (`rollout/replicaset.go:shouldDelayScaleDownOnAbort`). Fast-rollback detection (skip pause/analysis when re-deploying an RS still within its scale-down deadline): `rollout/sync.go:isFastRollback`, `isRollbackWithinWindow`.
- **AnalysisRun reconcile** (`analysis/controller.go:syncHandler` → `analysis/analysis.go:reconcileAnalysisRun`): resolve args → `ValidateMetrics` → `generateMetricTasks` (interval/count scheduling) → `runMeasurements` (one goroutine per metric; calls `metric.Provider.Run/Resume/Terminate`; updates `MetricResult` counters `Successful/Failed/Inconclusive/ConsecutiveError/ConsecutiveSuccess`) → `assessRunStatus` → `assessMetricStatus` → `assessMetricFailureInconclusiveOrError` (the actual semantics: `result.Failed > failureLimit` ⇒ Failed; `result.Inconclusive > inconclusiveLimit` ⇒ Inconclusive; `result.ConsecutiveError > consecutiveErrorLimit` (default 4) ⇒ Error). Worst-of aggregation via `utils/analysis/helpers.go:IsWorse`. Measurement pass/fail itself is `utils/evaluate/evaluate.go:EvaluateResult` — expr-lang evaluation of `successCondition`/`failureCondition` against `result`; neither matching ⇒ Inconclusive. `calculateNextReconcileTime` self-enqueues for the next interval.

## Public API

- **The CRDs are the API.** External programs create/patch `Rollout`, `AnalysisTemplate`, `ClusterAnalysisTemplate`, `AnalysisRun`, `Experiment` (group `argoproj.io/v1alpha1`, registered in `pkg/apis/rollouts/v1alpha1/register.go`). Generated typed clientset/informers/listers: `pkg/client/` (`clientset/versioned`).
- **Imperative operations are status/spec patches**, exported as plain functions usable as a library:
  - `pkg/kubectl-argo-rollouts/cmd/promote/promote.go:PromoteRollout(rolloutIf, name, skipCurrentStep, skipAllSteps, full)` — merge-patches `status.currentStepIndex`+pause conditions, or `status.promoteFull` + `spec.paused=false`.
  - `pkg/kubectl-argo-rollouts/cmd/abort/abort.go:AbortRollout` — patch `{"status":{"abort":true}}`.
  - `pkg/kubectl-argo-rollouts/cmd/retry/retry.go:RetryRollout` — patch `{"status":{"abort":false}}`.
  - `pkg/kubectl-argo-rollouts/cmd/undo/undo.go:RunUndoRollout` — rewrites `spec.template` from the target revision's ReplicaSet (works through `workloadRef` too via `undoWorkloadRef`).
- **gRPC/REST** `RolloutService` (`pkg/apiclient/rollout/rollout.proto`): `GetRolloutInfo`, `WatchRolloutInfo(s)`, `PromoteRollout`, `AbortRollout`, `UndoRollout`, `RetryRollout`, `RestartRollout`, `SetRolloutImage` — served by `server/server.go` (the dashboard backend).
- `utils/rollout/rolloututil.go:GetRolloutPhase` / `CalculateRolloutPhase(spec, status)` — canonical health derivation (`Healthy`/`Progressing`/`Paused`/`Degraded`), the same logic Argo CD's Lua health check mirrors.

## Extension points

- **Metric providers**: implement `metric/provider.go:Provider` (`Run/Resume/Terminate/GarbageCollect/Type/GetMetadata`, all returning `v1alpha1.Measurement`). Registration is the switch in `metricproviders/metricproviders.go:(*ProviderFactory).NewProvider`. Out-of-tree: hashicorp go-plugin RPC — interface `metricproviders/plugin/rpc/rpc.go:MetricProviderPlugin`, wired by `MetricProvider.Plugin map[string]json.RawMessage`.
- **Traffic routers**: implement `rollout/trafficrouting/trafficroutingutil.go:TrafficRoutingReconciler` (`UpdateHash`, `SetWeight`, `SetHeaderRoute`, `SetMirrorRoute`, `VerifyWeight`, `RemoveManagedRoutes`, `Type`). Built-in mapping in `rollout/trafficrouting.go:NewTrafficRoutingReconciler`; out-of-tree via `rollout/trafficrouting/plugin/` RPC and `spec.strategy.canary.trafficRouting.plugins`.
- **Canary step plugins**: `rollout/steps/plugin/rpc/rpc.go:StepPlugin` (`Run/Terminate/Abort`), driven from `rollout/stepplugin.go:(*stepPluginContext).reconcile`, configured by the `plugin:` canary step (`PluginStep` in types.go).
- **Plugin distribution/config**: `utils/config/config.go` parses the `argo-rollouts-config` ConfigMap keys `trafficRouterPlugins`, `metricProviderPlugins`, `stepPlugins`; `utils/plugin/downloader.go` fetches binaries (URL + optional sha256/headers).
- **Analysis composability**: `AnalysisTemplateSpec.Templates` lets templates reference other templates; flattening/merging in `utils/analysis/helpers.go:FlattenTemplates/MergeArgs`. `DryRun` metrics count toward `status.dryRunSummary` but never fail the run (`analysis/analysis.go:assessRunStatus`).
- **Workload ref**: `spec.workloadRef` (`ObjectRef`, incl. `scaleDown: onsuccess`) resolved by `rollout/templateref.go:informerBasedTemplateResolver.Resolve` — dynamic informer watches the referenced Deployment and re-enqueues affected Rollouts.

## Notes for integrators

- Promotion/abort are **status subresource merge-patches**, not spec edits; the CLI falls back to unified patches for pre-v0.10 CRDs (`PromoteRollout` comment). Automate against the same patches rather than inventing your own.
- Analysis abort is one-way per reconcile: `status.abort=true` persists until something clears it — `retry` (patch abort=false), a new spec change, or `promoteStable` (`rollout/sync.go:1322-1323`). The rollout stays `Degraded` while aborted with an unreachable desired template.
- `Inconclusive` ≠ failure: it pauses (`PauseReasonInconclusiveAnalysis`) and requires manual `promote` or `abort` (`rollout/pause.go:requiresManualAction`); `promote` on an inconclusive canary increments the step index and clears controller pause (`promote.go:getPatches` default branch).
- `failureLimit` semantics are `>` not `>=` (`failed > failureLimit`, default 0 ⇒ first failure kills the metric); `consecutiveErrorLimit` default is 4 (`utils/defaults`); provider errors (e.g. Prometheus unreachable) count as Error, not Failed.
- Canary without `trafficRouting` is replica-weighted only — pod counts approximate weight (`CalculateReplicaCountsForBasicCanary`); precise weights need a router. `setCanaryScale` decouples replicas from traffic weight; `dynamicStableScale` trades instant-abort capacity for fewer pods.
- Argo CD integration is entirely convention-side: the Lua health check and resume/promote actions live in Argo CD's `resource_customizations/argoproj.io/Rollout/` (see `docs/FAQ.md`); they key off `status.phase`/`status.message` produced by `utils/rollout/rolloututil.go:CalculateRolloutPhase` and `rollout/sync.go:calculateRolloutConditions`. For the Deployment-replacement pattern, either convert the Deployment to a Rollout wholesale or point `workloadRef` at it (`scaleDown: onsuccess` zeroes the Deployment after first promotion, `rollout/sync.go:1362-1368`).
- Blue/green `scaleDownDelaySeconds` (default 30s) exists for endpoint propagation; the delay is tracked as the `argo-rollouts.argoproj.io/scale-down-deadline` RS annotation, and an RS still inside its deadline is what makes `isFastRollback` skip pause/analysis on rollback — relevant if you build tooling that flaps versions quickly.
- One controller binary can run analysis-only (`cmd/rollouts-controller/main.go` `controllerAnalysis` mode via `NewAnalysisManager`) — useful for sharding AnalysisRun load in namespace-scoped installs.
